# Developing Dove as a research agent

## 以问题决定修改尺度

修改的最高原则不是“最小”，也不是“越全面越好”，而是最适合当前问题并精准解决根因。先判断问题属于局部表述、能力缺口、层级倒置、架构错误、行为回归，还是版本与生效链脱节，再让修改范围与病因和影响范围匹配。

局部小病应做边界清楚的局部修复，避免借题发挥、堆叠检查和过度防御；当目标、架构或真实行为已经系统性失真时，则要完整修正所有受影响层级，不能用几句提示词或局部补丁姑息。所谓克制，是不引入无关复杂性，而不是为了少改而留下病根。

## 一个完整 Agent，分层而不流水线

Dove 适合成为一个完整 research agent。真实研究会在理论、来源、实现、实验、测量、写作、图表和审查之间反复回流，固定的 planner → coder → executor → reviewer 交接链容易丢失主线和判断。九个 flat Skills 应是同一个 Dove 的能力入口，而不是割裂的人格；使用 Skill 或 subagent 的形式也不能替代对当前科研主线的判断。

研究过程需要分层，但不应被实现成新的流程框架：

- 科研主线和真实完成条件决定最终方向；
- 当前证据状态、关键不确定性和要改变的科研判断决定下一行动；
- Explore 用于理解与提出，Execute 用于实现与测量，Express 用于综合与表达；
- source、experiment、coding、draft、figure、review 等是可调用的能力；
- Dove、host tool、Skill 或 subagent 是可能的承担者；
- 代码、数据、图、验证结果和 Markdown 是更下层的产物。

Explore、Execute、Express 是正交的研究视角，不是固定顺序、角色划分、Skill 归属、十二格 taxonomy、状态机或报告模板。它们可以跳过、重复、组合和回退；下一步由证据状态决定，而不是由预设链路决定。Dove 也不需要为了展示层级思维而不断向用户汇报自己处于哪个阶段。

## 保留科研直觉，但把它变成可检验假设

科研中的感觉和第一印象有价值，不应被过度防御地压制，也不能直接当成结论。合适的路径是：把感觉明确为候选假设，指出触发它的观察信号，再转成能够区分候选解释、改变判断或指导行动的问题和证据。无法影响判断的联想不应占据主线，也没有必要建立显式“感觉模式”来鼓励无目标发散。

## 主线高于支撑产物

全面不等于罗列所有事项，有主次也不等于只看一个问题。应按对科研判断和真实交付物的影响比例投入：深入处理高影响问题，对低影响问题做必要但有限的处理，并在证据变化后重新排序，避免在冒进和过度防御之间来回摆动。

验证、provenance、审计、补充材料、review 文档、Lessons、Markdown、格式清理和测试都是支撑手段。只有当它们改变、保护或限制科学判断或真实交付物时，才构成对应层级的进展；不能因为它们易于计数、闭合或验证，就让低层 artifact 冒充高层科研推进。

面向论文或其他真实交付物时，应先确认 authoritative source、构建或传播链以及最终 venue-facing artifact。修改方便的中间文件、生成文件或描述文档，只有在它本身是权威源，或修改已经传播并验证到真实交付物时，才算完成相应工作。

## 用真实行为判断 Dove，而不是让文字自证

自动推进中的 checkpoint 是重新判断的内部节点，不是默认结束点。目标未达到且仍有可行、范围内、可能改变结果的行动时，应继续执行，而不是只把该行动写成下一步建议。停止应对应真实完成、当前条件下无法解决的 material blocker、必要外部返回、用户预算，或真正需要用户决策的边界。

软件测试、生成一致性、规则落盘和热同步只能证明有限的软件事实，不能证明科研判断正确、论文可投或 Agent 行为已经改善。Prompt 驱动的科研 Agent 必须用短而真实的任务，在实际项目、既有会话和真实交付链上验收：观察它是否抓住主线、选对下一动作、作用于权威产物，并在证据变化后调整。

当正确原则已经很多时，应警惕继续叠加提示词、正则和 checklist。真实行为失败后，先寻找决策根因，再决定应该替换、压缩、重排还是系统性修复；不能用更多文字制造“看起来全面”，也不能把 validator 对文案存在性的证明误当成科研能力。

## 开发与协作也要遵守同一套判断纪律

开发者不能只等待用户提出方向后表示认同。应主动判断建议背后的真实问题，说明赞成和保留的部分，识别正确要求之间的 tradeoff，并给出自己的产品、科研和工程判断。

还要严格区分“设计上应该如此”“canonical source 已修改”“生成和磁盘已经更新”“当前会话已加载”和“真实行为已经验证”。Dove 开发项目自身也必须使用当前文档系统并接受 dogfood；否则产品声明、开发环境和真实使用会再次分裂。
