# Hook Guidelines

This file governs **Dove product integration** in consumer projects, not this repository's Trellis development hooks or subagents. Canonical sources and packaged projections are mapped in [Directory Structure](./directory-structure.md).

## Host integration

Claude Code receives the complete Dove integration; DeepSeek Harness receives project-local filesystem Skills only, without Claude permissions, hooks, or MCP projection. Hosts route work and enforce permissions; the shared research rule is guidance, not a router or permission grant. Research/delegation responsibilities belong in [Component Guidelines](./component-guidelines.md).

Claude integration owns only the documented `.mcp.json#/mcpServers/dove-paper-search` and `.mcp.json#/mcpServers/exa` fragments, project-scoped `permissions.deny` for built-in `WebFetch`, and a `statusLine` fragment when that setting was empty at installation. Pinned paper search serves scholarly discovery, download, and full-text reading; hosted Exa serves ordinary webpages, documentation, venue pages, and known URLs. Built-in `WebSearch` remains available for discovery. Hidden guidance Skills and status display do not grant tool access. Runtime dependencies, project trust, tool approval, access, and credentials remain user-provided; do not substitute CLI/shell/`curl`/fetch scripts for unavailable web retrieval. These external tools are not Dove research-state services.

## Read-only product SessionStart

- Invoke user-installed `dove` on `PATH`, not a copied runtime or absolute installation path.
- Inspect the exact initialized project and same-package manifest revision `2.0` without writing files or shared configuration.
- If integration is not current, report a `systemMessage` suggesting explicit `dove update`; unsupported or ambiguous state needs `dove doctor --json` and manual resolution. Never update, adopt, migrate, clean up, or reinstall from the hook.
- Startup and `/clear` emit a small author-preference bootstrap after valid inspection, even without an integration warning. It requires the current host main agent—ordinary Claude or explicit Dove—to personally read the full installed reference before substantive work; it does not embed the body or delegate the read. Compact/resume shows the short identity card and continuity reminder without an unconditional full reread.
- Inspection and bootstrap delivery cannot verify reading or retroactively reload already-active Claude context. npm global `postinstall` may independently synchronize registered projects during an upgrade; SessionStart itself stays read-only and never triggers that sync.

## Compact/resume identity card

After compact/resume, show the short researcher-owned identity card and a brief reminder to compare the latest correction and results against the goal. Reuse author preferences read in the same main context. The hook does not scan overview, Review or Run timestamps, transcripts, research reports, or logs; it cannot choose scientific actions or certify reading. Missing or unreadable cards remain missing, not inferred from old notes. Startup/clear emits the separate author-preference bootstrap, not a second research summary. No new ledger, Auto Skill, Stop hook, or time quota follows.

## Read-only status line

- When a Claude project has no existing `statusLine`, install the manifest-owned command `dove hook statusline --project "$CLAUDE_PROJECT_DIR"`. A pre-existing user or Trellis line remains unchanged and unowned; an empty slot may be filled by a later explicit update.
- Preserve the explicit absolute project path. Consume only Claude Code's native status payload for model display name, total context capacity, remaining-context percentage, and current-session duration, and read the Git branch from that project root with a bounded no-shell command. Missing host facts are omitted rather than represented as zero.
- Keep the renderer fast, read-only, and offline. The first line keeps model/context/branch/session facts and replaces the project-path slot with the mainline text in cyan, without a label; only a nonempty `NO_COLOR` disables color. The second line is only the absolute project path. Read the user's confirmed Mainline from the short project identity card, never from a growing `RESEARCH.md` or inferred from Git, Mission, Run, or Review. Missing or unreadable identity is omitted rather than guessed. Do not scan the research tree or access Review, Run, transcript, or durable timer content. Git branch remains an active work branch, not a confirmed scientific mainline; session duration is not cumulative research effort. This narrow display read does not change SessionStart.
- Doctor inspects managed drift read-only. Explicit update/reinstall may restore an edited manifest-owned line and report it; host removal/uninstall removes an unchanged owned line while preserving a user-modified one.

## Short per-prompt re-anchor

Claude's existing managed `UserPromptSubmit` makes the project's short researcher-owned identity card visible on each prompt when integration is current, replacing rather than stacking long reminders. The card records the user's own Mainline wording, inputs/outputs/completion meaning, rejected methods and prohibitions, route, next core action, and hard blocker. The main agent uses it before writing plans or delegating; no hook turns the card into a permission gate or inferred acceptance criterion. This delivers fresh hook context to an already-open session whose hook remains registered, **not** host-level rule, hook, Skill, tool, or permission reloading, and does not prove reading or application. If integration is uninspectable, stale, or drifted, emit a nonblocking attention-only message; do not inject unverified guidance. Do not classify prompts, write research material or transcripts, make permission decisions, block submission, or call a model or tools to select work; bounded card reads are presentation, not research judgment. Keep bounded requests bounded. Research judgment stays in the main agent; no Research Spine schema, ledger, or per-session read-status file follows. SessionStart's inspection and bootstrap remain read-only; compact/resume shows the same short identity card. DSH remains filesystem Skills only. Without an already registered, executable prompt hook, or for full host-level loading, a fresh host context is still the reliable boundary; disk bytes alone do not establish live loading.

## Native session continuation is not an integration hook

When available, Claude's native `CronCreate` supports same-session continuation of an open confirmed goal, not a new gate. Do not delete a user-set goal or loop. On each wake recheck the identity card and evidence and perform substantive core work; running training, a completed diagnosis, or a status report alone is not a reason to end or poll without advancing. It is not installed or controlled by Dove hooks, cannot extend a bounded/read-only/design-only request or denied permission with no other effective work, and provides no DSH or session-exit recovery guarantee. No Stop-triggered scheduler, Auto Skill, hidden ledger, or new permission follows; only cancel a pending wake owned by the session when work must stop. See [Component Guidelines](./component-guidelines.md) for the research decision boundary.

## Prohibited and retired product integration

Dove installs no hidden intake, ambient router, blocking Stop scheduler, or per-tool scientific approval. The dormant compatibility `dove hook stop` command cannot know the user's active request from Stop input and emits no blocking or turn-continuation output; ordinary installation does not register it. Stop must not manufacture another research turn or write research state. Explicit lifecycle operations remove a retired prompt fragment only when still manifest-owned and digest-matching. Unowned legacy Stop/prompt entries and unknown files remain untouched; diagnostic recognition is not deletion authority.
