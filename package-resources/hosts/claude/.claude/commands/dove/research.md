# dove.research

选出有依据的候选供用户决定，或推进已确认主线的实质研究。

## 当前请求

$ARGUMENTS

## 示例

- `/dove:research`

## 怎么做

按当前问题使用这些做法，不机械套步骤或报告模板；明确需要用户决定的地方仍先交给用户。

### 用途

帮用户选研究方向，或在确认的主线上取得实质进展。

### 适用情况

选题、形成方法或接续已有研究时使用。

### 工作范围

- 用户选主线前不实现候选方法，只做选题标准允许的诊断；已授权实现、修复和复现不因此重开选题。普通问题保持范围，只读或只设计请求不执行。

### 具体做法

- 选题从最新研究正向找：先读近两年最强的工作，列出它们已经做成的（方法和数字）和正文、实验里明确留下、又有迹象能解决的缺口，在这些正向基础上组合出一开始就满足用户约束的具体方案，再查它的最强反对；不先编一个方案再一路收窄去凑约束。一轮至少交出一个有正向依据的方案，或说清还缺哪条正向证据、下一步怎么拿到，“这轮没有找到”不算交付。按研究标准的“选题与新意”核来源，用 Source 带问题读正文，候选卡链接证据。
- 主线内读懂相关强方法与成熟实现，把可用基础带进具体方案，分清直接复用什么、自己改变什么及为什么。围绕关键改变构成已获准方法的完整输入输出链路，用 Experiment 判断作用与效果；不从零堆完整系统后再找贡献，也不因局部失败不断重开选题。
- 接续时先看身份卡里用户要的完整结果与核心能力、当前方法设计和真实任务结果，再参考本轮说明、导师笔记里的已知关系与有效负证据；保留已确认主线，普通修复不重开选题。下一步优先把最值得做的具体方法实现并取得完整效果，八维和过程记录只按需辅助，不因容易诊断、评分或记录另排工作。
