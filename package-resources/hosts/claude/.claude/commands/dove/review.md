# dove.review

独立审指定当前论文，或检查局部产物、交付就绪和已有意见。

## 当前请求

$ARGUMENTS

## 示例

- `/dove:review`

## 怎么做

按当前问题使用这些做法，不机械套步骤或报告模板；明确需要用户决定的地方仍先交给用户。

### 用途

评估论文科学质量、局部产物、交付就绪或已有审稿意见。

### 适用情况

判断论文或检查审稿时使用，不代替导师定方向。

### 要判断什么

- 作者自查用具体证据和可行动修改批评当前论文，不冒充独立审稿。
- 交付检查核对实际投稿要求、构建／导出结果和材料，交付就绪与科学上可接受分开判断。

### 工作范围

- 审稿是有理由的反对，不是实验证据或自动接受。作者判断依据并处理重要担忧；作者自查不能证明独立审稿。

### 具体做法

- 完整论文问四件事：方法回答研究问题了吗；机制、术语、比较、文献、反例与边界在该领域是否正确；贡献、证据、范围和表达是否适合目标场合与读者；最强合理反对是什么，需要什么证据或修改来回应。
- 独立审稿在全新只读上下文调用 dove-review，给当前稿、所引结果与相关实读投稿／文献材料。它用 Read/Grep/Glob 读指定文件，不接收作者执行对话，不需冻结快照、审稿 CLI 或持久会话。这是看证据的审稿，查主张、比较和数字。
- 语言与排版对照审查另做，放在交付前冷读之前：调用正文以‘语言与排版对照审查’开头，附上 Draft 的逐句语言、表格论证组织与排版检查项，给当前稿和补充的 PDF 页面（含图内文字）、相关排版源码、稿件旁 REFERENCE_LAYOUT 和其中记录的录用论文 PDF；让全新只读 dove-review 逐句逐表对照，不只看能否读懂，按影响返回页码、原文 → 可替换英文或排版改法、对应参考页码与理由，原样保存有用意见。区分参考论文惯例与个人偏好，不照抄句子、不为换说法改量名，不用润色削弱有据主张；缺材料就报告缺口。主会话交 Draft 与 Figure 处理、重编译后，再另开全新读者冷读当前 PDF，不把参考论文或对照意见带给冷读者。这一遍不替代科学审稿，冷读也不替代这一遍。
- 冷读另做，交付前和用户要外行视角时都做：dove cold-read --project <root> --pdf <稿件.pdf> [--pdf <补充.pdf>] [--venue <投稿目标>] 把编译好的 PDF 转成逐页文字和页面图片，并输出调用正文；把正文原样交给一个全新的 dove-review，只给这份 PDF，不给 tex、读数文档或项目背景，那是开发者视角，会把注意力引到核数字上。写稿的人在项目里泡久了，查不出自己的行话，冷读不能用自查代替。冷读结果原样存到稿件旁，分成“必须改”和“可改可不改”，另列事实/数字疑点供掌握原始读数的一方核对：行话在第一次出现时定义或换成通用说法，读不懂的地方先改稿（这类问题通常不是靠解释给读者解决），防御措辞删掉或集中到局限段；冷读者建议加限定或削弱强项时按证据和扬长避短取舍，不照单全收。图表和版面问题交给 Figure 和 Draft；逐条处理必须改项，重新编译后再由全新读者冷读，直到必须改项清零才交付。
- 返回简洁判断、阻挡问题、证据、作者可做的修改和实际读过的文件；材料不足就限定判断。整篇审稿读完整当前版，局部审查保持局部；实质修改后需重审完整新版，旧建议才可视为当前。
- 忠实保留真实审稿返回，区分用户贴来的意见与实际完成的独立审稿。有用返回放普通项目材料，不建运行时交换库；阅读或保存本身不授权修改或重审。
