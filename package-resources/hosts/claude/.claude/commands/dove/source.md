# dove.source

查读来源、核引文与主张，把发现用到研究决定中。

## 当前请求

$ARGUMENTS

## 示例

- `/dove:source`

## 怎么做

按当前问题使用这些做法，不机械套步骤或报告模板；明确需要用户决定的地方仍先交给用户。

### 用途

发现、获取、阅读和核实能改变研究决定或回答具体问题的来源。

### 适用情况

查文献、读来源、核引文身份和主张、比较相关工作或系统综述时使用。

### 工作范围

- 片段、摘要、元数据或没搜到结果，都不能证明读过全文或不存在重合。工具缺失或失败就用 WebFetch、arXiv／Crossref API、curl 下载等方式取来源，说清实际读到什么。

### 具体做法

- 从用户问题和已有笔记出发，分清发现来源、核实引文身份、读正文、证明主张，互不替代。引文先查 DOI 再模糊搜标题，核对标题、作者、年份、场合／版本，报告冲突、缺失与未知。投稿前逐条联网核参考文献是否存在、版本与卷期页码，优先出版方或正式会场页面；引用正式版就用正式版作者与元数据，不混用预印本作者表。描述工作还须有正文依据，元数据核实不代替实读；是否引用预印本按项目要求，不把单项目偏好推广为禁令。
- 正文细节带 1–5 个具体问题读全文，按研究标准在 `.dove/research/papers/<id>.md` 累积问答。复用旧答案，只补新答并标章节、页码或公式，保留旧答；只核查的任务返回答案，不建笔记或改稿。
- 拆开复合主张，逐项标支持、反驳或未覆盖，附相关段落、公式、算法或代码及限制。新意和重合判断用累积笔记，链接受影响产物，建议与实际支持一致的表述，不拿半句支持整句。
- 跨领域按相同贡献粒度找真实近邻，选题时按选题标准。从来源的真实问题、有效机制和可获得的实现形成候选；按当前问题读核心算法、相关代码和适用条件，说明可直接借用什么、还需改变什么及怎样接入。不先定方案再收窄问题，也不以全面否定已有工作代替设计；找不到实现就说明，不把发现代码当读懂或验证。近邻与反例用于校准，重合不自动否定改进，已覆盖贡献也不靠改名恢复；带回已有设计或论文笔记，继续检索已不会改变决定就停。
- 明确做系统综述或元分析时才定义问题、检索范围、纳排标准，按适用 PRISMA 记录、偏倚与证据把握评估，只合并可比效应。普通检索不加这套流程；有用链接或综合认识改变时才更新 `sources/SOURCES.md`。

### 使用宿主工具

- WebSearch 用于发现来源，dove-paper-search 查 DOI 元数据和论文，普通网页与已知链接用托管 exa 或 WebFetch。
