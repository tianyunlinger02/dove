# dove.experiment

解释真实结果以形成方法，用公平比较、有效诊断和可靠分析检验。

## 当前请求

$ARGUMENTS

## 示例

- `/dove:experiment`

## 怎么做

按当前问题使用这些做法，不机械套步骤或报告模板；明确需要用户决定的地方仍先交给用户。

### 用途

开发、复现和评价方法，让证据回答研究问题。

### 适用情况

已授权的开发、诊断、确认、复现或结果分析时使用。

### 工作范围

- 只读或只设计不执行；用于调参的保留集不再是独立最终证据。

### 具体做法

- 解释结果前查相关代码、数据、配置、输出与分析，先核对核心计算是否完整、失败发生在哪一步。缺实现就补，已知原因就修，关键原因尚不清楚才用诊断区分解释；按研究标准的“从问题到方法”推出改法和预期。新方法或新核心模块先交方法设计让用户看过；模型学不会时可用单例过拟合诊断学习机制，不先靠更多数据或更大评价器补救。
- 按完整方法预期改善的真实效果和噪声定规模、对照与判定，互不依赖的方案可以同时试。开发按会改变方法选择的未知做必要测试，不要求每次修改全评；诊断结束落实到具体改法，不以补齐记录、局部指标提升或反例清单代替完整方法结果。正式效果仍须真实任务评测，训练或合成分布不能替代。
- 完整任务对强同输入外部方法判断效用，消融和受控比较判断归因。预算、不确定性及失败、缺失、无效输出怎么算都写清；正式比较按研究标准“证据与实验”的协议执行，未测效果留未知，新版不继承旧版通过结论。
- 论文核数由掌握原始读数的一方从当前 JSON、日志或分析输出重新计算、一次舍入，不拿稿件之间一致当数字正确，也不二次舍入。复核统计定义、单位、分母、子集与处理阶段：各阶段中位数相加只能叫阶段中位数之和，不是总耗时中位数；到达 token 上限不是超出；中位穿透为零不是所有穿透消失；覆盖率上下界须说清是逐样本量、这些量的中位数还是其他统计。正文每个结果数在正文表中有对应项，或就地说明来源；变更数字后交 Draft 同步全套，再冷读，不让只看 PDF 的读者核原始读数。
- 主执行者修评价并立即标受影响结果；先复用原始输出，恢复当前主张、必要历史比较和强基线的可比性，再重跑必要版本。不用于当前判断的旧结果可标旧协议历史，用前再恢复，不要求先重跑全部历史，不混协议、不藏负证据。只修协议不等于换方法版本；若改变目标含义就问用户。
