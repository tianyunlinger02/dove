# dove.draft

据证据写改权威稿件，也按审稿意见修改并写回应，沿实际构建或导出路径交付。

## 当前请求

$ARGUMENTS

## 示例

- `/dove:draft`

## 怎么做

按当前问题使用这些做法，不机械套步骤或报告模板；明确需要用户决定的地方仍先交给用户。

### 用途

写作、评估或修改指定稿件、章节或承载主张的产物，也包括按审稿意见修改和写作者回应。

### 适用情况

用户要求写改，论证、表达、交付产物需要处理，或要回应、落实审稿意见时使用。

### 工作范围

- 只评估就只返回发现，不编辑。局部写作不因读材料就强加导师、新轮次或子代理；准备产物不等于获准投稿。作者回应与修改限于请求范围，不授权投稿或破坏性操作。

### 具体做法

- 读目标文本与主张证据，动笔前先回答：审稿人读完摘要应记住哪个论点？方法论文让读者看清复用的基础、自己的关键改变、为什么这样改变及证据支持的作用，用它连起问题、缺口、洞见、方法和边界，而非模块清单、‘系统更好’或一串结果。论证随实际方法与证据修正，不为预定故事反向拼装方法或挑结果。同一论点的多组证据并排讲，最重要的发现放进摘要和引言，说明能力转变及其意义。改写不暗中加强或削弱确定性、因果、范围、数量和新意；证据要求改主张时先说明。处理范围内的来源、方法、证据或图缺口，不只弱化文字，文笔好不等于贡献成立。
- 写作沿用用户当前权威稿件格式，找到源文件和构建／导出路径，遵守实际投稿要求。只有新稿且投稿方接受时默认 LaTeX，否则用要求格式。检查实际提交产物（LaTeX 要看编译结果），科研证据与投稿材料分开，已授权修改都落实到权威源文件。
- 动笔或大改前，选 2–3 篇同方向、同投稿版式、近两年已录用的论文，优先作者已引用的强相关工作，读 PDF 原文逐项对照：各节篇幅和首图页码；引言每段怎样从问题、已有方法缺口推到核心想法和贡献，实验怎样按结论、图表、解释组织；每张图表承担什么证据、放在哪里；介绍贡献、报告主结果、写消融和局限时的典型句式与用词，以及字体、记号和表格惯例。记下页码和本稿采用的决定，放在稿件旁（如 paper/REFERENCE_LAYOUT.md），同一篇稿件复用，写改时逐项对照。学论证结构和句子功能，不照抄句子，也不照搬图表数量。
- 动笔前在稿件旁列‘内部名 → 论文用语’读者词表，同一稿复用，正文、表格、图内标签、补充和已有中英对照阅读版都从它取名，改名后全套同步；轮次、实验臂名、内部路径、调试状态和协议代号不进稿件。集合首次出现说清大小与用途，用 test set、development set 等读者能懂的名字；缩写和自定义概念在正文首次出现处用半句白话解释，不只在补充定义。一个量只用一个名字和符号，定稿时逐项核对全文、图表和补充；模型名、参数量与版本各指什么也说清，不另造第三个名字。
- 逐句检查论文语言，不只查能否读懂：核心论断是否在摘要、引言和结论里机械复述同一固定说法，可用全文检索定位，按段落功能合并或改写，但同一量和技术术语不为换词而改名；顺手自造的概念词能否换成直白描述，比喻是否侵入方法和实验而模糊真实操作。核对介词搭配、施事主语和悬垂修饰语，无生命主语须确实能承担该动作；分别对应的两组对象用 respectively 或拆句说清，which、it、each、both、its 都就近指明对象。摘要、引言避免口语反问，小标题优先目标场合常见的陈述式，不写成问句加 No. 开头的问答；参照录用论文在引言用 We present <方法名> 等框架点名，贡献用 We introduce / We train / We show 等完整句而非加粗口号，结论回顾已做成什么（如 We introduced），按本稿内容写，不套固定原句。定性说法也核对表中数字，seconds rather than minutes 这类对比只有数字确实支持才用。
- 先按投稿正文页数定版面预算再写，与 Figure 共用稿件旁同一张‘论点—证据—位置—尺寸’表：每条论点由哪张图或表支持，正文还是补充、靠近哪一节，单栏还是通栏、实际栏宽和目标高度。图表总量按预算定，正文写满允许上限（如 CVPR 8 页、不含参考文献）；正文变短时优先把补充里直接支撑论点的证据移回，再补必要的动机、直觉、例子和分析，不填空话。压版面先删复述表格的总结段和重复结论句，再把外围内容移到补充；支撑核心论点的数字（含复现与逐项配对结果）留在正文，可写成句内数字，补充只放更细的拆分，不先压掉必要解释或核心证据。联动顺序是 Draft 定预算 → Figure 按尺寸画 → Draft 放入、核图注和引用、编译看版面；不合适先调位置与取舍，必要时请 Figure 改尺寸，并更新同一张表。
- 表格按论点而非实验顺序组织，也写进同一张‘论点—证据—位置—尺寸’表：多组证据证明同一规律时，合进一张表、共用同一组指标行，把各组特有的指标放在分区；不同模型、子集与分母在对应列或表注说清，不因合表混成同口径比较。以一节一张主表为组织原则，不把另一节的论点证据塞进来；不是表格数量规定，简单论点可用一句话加图，信息需要时也可分表。表注与图注一致，粗体标题直接写证据支持的结论，设置、单位和口径随后说明；也可用短主题标题接一句结论，按同篇实读参考统一，不把集合名、面数或样本数塞进标题。别扭的单行可改成表注或正文数字，但不移走核心证据。交付前逐表问：支撑哪个论点？不看正文能否从表和表注读出它？是否混入别节证据，或有只占位置的复现行？按论证作用调整位置与形式，直接支撑论点的复现和逐项配对结果仍留正文。
- 按论文写，不写成实验报告，立场是扬长避短：贡献和强项正面陈述，证据直接给关键数字。限定只在必要处说一次，集中放在局限段；局限段只列真正必要的边界，不罗列每个小缺点；弱项在正文一两句带过、说清能改进的方向，细节放补充材料；不在摘要结尾、正文各处或图注里反复加免责。摘要一般按“问题 → 已有方法的不足 → 核心想法 → 由此获得的能力 → 一两句关键结果 → 机制上的结论”写，只带一两个关键数字；实验每段先给发现，再指向图表，不用 We take 200…、For each of… 这类操作开头；流程进 Setup 或补充，默认设置、选样与匹配约定在 Setup 说一次，实际差异仍在相应图表就地交代。叙述用百分比和一两个关键数表达发现，不堆计数串；必要分母与逐项配对证据保留在表中或论证句里，不为去报告腔删证据。直接支撑核心论点的数字与分母留在正文表格或实验叙述，协议、设置与细分结果在相应表注、实验节和补充展开。缺材料问作者，不把‘未提供’塞进稿件。在准确和投稿规范内检查整篇论证影响，不把局部写作扩成新研究。
- 在指标定义处写清成功口径：各方法要完成哪些步骤、无效或失败输出怎么算，不让‘生成完成’与‘经过后续仿真和检查通过’只靠表注区分；表里写分母及计数单位，是样本、编辑次数还是别的。并列的数字来自不同模型、规模或样本子集时，就在该句数字旁标明，不让读者去补充里找；比较使用同一层级和同一口径，不拿结构有效率直接比仿真通过率。主动交代影响比较的训练数据、上下文长度、解码上限和计算预算差异，实际测到的基线成功率与集合规模直接给，不用‘时间限制’带过。数字从原始未舍入读数按约定单位与精度一次舍入，不从旧稿或已舍入数字再抄；结果更新后同步所有引用处。
- 对照投稿模板和参考论文实看字体、表格与全文惯例：行内代码和 token 用与正文字体配套的等宽体，保持正文正常字号，不用 \small 缩号；放大渲染段落看字高、粗细，并与图内 token 对齐，不为所有论文硬定一种字体。表头写清指标方向（↑/↓）和单位；需要两行时指标名一行、单位与箭头一行，用整行结构对齐，避免逐格 \shortstack 造成高低不齐。单元格不重复单位，同列精度一致，分母仍在表内说清；文字和数字用与正文配套的文本字体，不用数学粗体代替普通数字加粗，表注说明实验设置与加粗含义，不塞进左上角；行名用准确语法。超宽先将表头分行或缩短行名，再调列距或布局，不用 \resizebox 整体缩表。正文、补充和图内文字同遍检查标题大小写、美式拼写、千分位与 vs. 等写法；图中失败标签按实际失败类型统一措辞，图例靠近对象，实看易混字形和方法名。
- 用 `.dove/research/papers/library.json` 和 `library.md` 按方向组织相关工作，每组以本文和这组工作的区别收尾；据 `papers/<id>.md` 核主张支持。引用或导出 BibTeX 前用 Source 核元数据，只导已核字段，不编作者、场合、日期或标识。显式积累或后续 watch 才更新库，只读不写。
- 写稿方负责 tex、图注与正文，出图方负责图内文字；任一方改动后，另一方回查同名、同符号、子图编号和引用，文字改名也要回查图，不只是换图后核图注。双方并行改稿或改图时分清各自文件；出图方要切分支就用独立工作区，若共用同一工作区则先交接当前分支与未提交改动，提交前核对所在分支，不把对方改动带进自己的提交；共享工作区不能隔离未提交改动，分支归属未交接清楚就先等对方交回，不直接提交。再走实际构建／导出路径，改表后也重新编译并看图表离引用的距离；需要相邻的通栏浮动体在源码中相邻、放在预期排入的页之前，按实际输出调整，不只查表本身；新增通栏图挤远主表时，试模板允许的 [!tb] 等浮动位置或撤外围图，不让关键表漂到两页外。每次编译都实看结论最后一行所在页，不只找 Conclusion 标题，小改也可能重排浮动体；溢出先删与前文重复的句子，再按版面预算取舍。编译后检查溢出框、未定义引用、图表编号、双栏宽表是否通栏，逐页看空栏、只放浮动体的栏、大片空白（dove figure --pages <稿件.pdf> --body-pages <正文页数上限> --output <总览.png> 把所有页排成一张总览，标出这些位置，并按参考文献标题算出正文实际用了几页），以及图表是否离首次引用超过一页、排到结论之后或参考文献页、正文是否提前结束而没用足页数。正文字数从源码算，排除表格、图注和参考文献，与目标核对；按投稿要求核对正文页数（含图表），保持最终字号和关键证据。收尾把全文逐页渲染，一次看完版面、图文邻近、图注一致和整套图风格，看过输出才称当前稿；修范围内问题，说明剩余材料限制。用户要的阅读版（如中英对照）在每轮实质修改后按当前权威源重新生成，补充图表编号取当前编译的 .aux，不凭记忆或写死；图件变化后预览图从当前导出 PDF 重出，不复用旧预览，交付前核对它们与源稿是同一版。
- LaTeX 稿件在投稿模板允许的范围内默认放宽浮动参数：\renewcommand{\topfraction}{0.9}、\renewcommand{\dbltopfraction}{0.9}、\renewcommand{\textfraction}{0.08}、\renewcommand{\floatpagefraction}{0.9}、\setcounter{topnumber}{3}。仍排不下时调整图表在源文件里的位置或内容取舍，不靠负间距或缩字号塞版面。
- 正文的论断及其证据数字在正文自成一体，补充指针只给更多细节，不用 Supp. Tab. 代替关键论证。主文与补充分开上传时，双向跨文件引用只输出编号、不生成跨文件链接；LaTeX 在模板支持下用 xr 读当前编译的另一稿 .aux、用 \ref* 输出无链接编号，不写死图表号。补充删完全重复的主文表，独有事实保留或改写成文字；自己首次引用的方法、数据集补齐文献，公式等编号按模板用 S 前缀区分。
- 补充材料是给读者的论文，不是开发记录：去掉无谓的 \clearpage、开发用样本 ID、原始路径、历史版本标签和横幅；样本与原始文件的追溯映射留在项目来源记录。必要的图片选择与可视化说明简洁并入协议节，不单独堆成过程说明。图表与算法用模板支持的浮动环境，不用整宽非浮动 minipage 硬排造成大留白；需要逐节收住浮动体时用 \FloatBarrier，使用 multicols 时把每节开头的屏障和节标题放在环境外，浮动体也按该环境支持的方式安排，实编译查漂移与交错，不向所有模板强塞同一包。只有图的小节补一句导读。
- 每次交给用户或投稿之前按顺序终检：主会话／Source 先联网核目标会议当届 CFP、Author Guidelines 和 author kit，核年份与模板版本、页数规则、必需声明、匿名与外链、补充要求、直接拒稿清单，以及摘要登记、账号、正文、补充的关键日期与时区；不沿用上届要求或记忆，逐条引用也按 Source 联网核。需要 LLM 使用声明时，按实际工具、用途、参与程度和人工复核给参照草稿，由用户定稿，不虚称未参与思路或套用别项目声明。数字分三层：Draft 先查摘要、引言、正文、表格、图注和补充的单位、精度、名字、数值及定性判断是否一致；掌握原始读数的一方再按 Experiment 重新舍入、核统计定义；最后才交只看 PDF 的新读者冷读，三层互不替代。冷读前按 Review 做语言与排版对照审查，处理后重编译，用 dove figure --pages 看版面。按 Review 冷读闭环逐条改，图内问题交 Figure，事实与数字疑点回原始读数方，不把读数塞给冷读者；改完重新编译，由全新读者复读，未解决的‘必须改’清零才称交付就绪。补充单独编译看版面，主文与补充的编号、引用都能找到；双盲投稿查作者信息、致谢、带用户名或机构的链接、第一人称自引、PDF 元数据和补充文件。后续核数或匿名修正又改稿，也重编译并复读当前版。交付说明写清核规来源、对照审查和冷读的发现、修改及有依据未采纳的意见；只查编译、页数和数字不算终检。这是写稿方自查，不另建审批，不阻断用户直接要的局部改动或要求用户批准检查。
- 模板缺字体或包时，用允许工具放在项目本地 texmf 并让构建使用，不静默换字体或改系统安装。
- 回应审稿意见时，读审稿、它读过的材料清单和当前产物，共因问题合并处理，核实依据，不全盘接受；按实质影响排序，决定接受、反驳、限定或调查，每个重要问题都覆盖。用 Source 核新引文与主张，用 Experiment 取得或解释结果；比较原主张、审稿理解、回应和改后主张，不暗改确定性、因果、范围、数量限定与新意。
- 按要求改证据、分析、文字、图表、补充材料或投稿文件，不只改语气；局部答复解决不了就修共因。逐项说明担忧已解决、减轻还是仍有限制，写了答复不等于解决或审稿人接受。审稿原文与作者回应分开保留，并链接到改动产物；依赖旧审稿建议前，按 Review 查当前版本。
