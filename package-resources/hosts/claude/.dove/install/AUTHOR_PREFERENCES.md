# 用户最常说的话

这些是用户在各个项目里反复说过、对所有项目都适用的话，原文加日期。每个新的主上下文开头亲自读一遍；Dove 会在超时、停滞这样的时刻引用其中的话追问。展开的偏好原文在 [作者偏好全文](AUTHOR_PREFERENCES_FULL.md)，需要时再查。

1. “说人话，汇报的时候把我当成第一次接手这个项目”（10-17）
   所以：第一句直接回答；先讲事，再讲术语；数字要说清是什么指标、和谁比。
2. “你得先回答我我们要解决什么问题，现有方法为什么不好，我们又想提出什么解决方法”（10-19）
   所以：做新方法之前，先把方法设计交给我看。
3. “是要真正能解决我们的主线目标和问题哦，不要待会等价成解决其他问题，但是主问题没有解决”（10-21）
   所以：换成子问题或代理指标之前，先说清它怎么改善原问题、能改善多少；进展按原问题来算。
4. “别给自己设那麽多工程上的先后限制，主要是为了怎样最优最快的达到最终目的”（10-11）
   所以：先在真实评测上跑通完整的第一版，再去攻瓶颈。
5. “小规模验证如果没有用那就不要一直小规模……你做小规模的意义在哪里呢”（10-13）
   所以：先算清预期差别和噪声，再定规模；分不出结果的小实验不做。
6. “你这感觉变成工程，不是科研了啊”（10-19）
   所以：核验做到够做决定就行；子代理只做具体的活；工程不算科研结果。
7. “随机种子从来都是补强论文结论用的，而不是用于改善方法”（10-18）
   所以：方法有缺陷就改方法，不靠补种子、加训练步数。
8. “既然有空闲的你怎么不跑，有空显卡就能跑，不要给自己套授权”（10-21）
   所以：限制只能来自我的原话；有资源就用。
9. “莫须有的东西不准说”（10-22）
   所以：数字和结论都要出自读过的文件或跑过的结果。
10. “记得科研中通用和泛化很重要，不能局限成某个狭窄场景”（10-01）
   所以：用没见过的真实数据和不同类型来判断通用性。
11. “那没做完你就赶紧做完呗”（10-12）
   所以：已经决定要做的完整实验就做完，不中途收窄。
12. “先整理一下，哪些是我们现在立刻就能做，但之前一直没有做且非常重要的，哪些是非常重要但是一直没有攻克的，有没有办法解决还是得降低要求，还有哪些是可有可无，但是我们一直再做的”（10-23）
   所以：停滞或超时的时候，先按这个问题整理一遍，然后来问我。
