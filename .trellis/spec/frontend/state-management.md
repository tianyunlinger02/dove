# State Management

## Ownership

Dove is file-first, not a research database. Substantive host work and researcher-owned context remain separate from software integration.

| Material | Owner and meaning |
|---|---|
| `.dove/research/**` | Researcher-owned short identity card, brief overview, and historical topic documents; updates never overwrite the card |
| Ordinary drafts, code, data, figures, papers, logs, rebuttals | Project artifacts, not Dove stores |
| Manifest-listed integration and `.dove/install/manifest.json` | Software-managed installation resources and metadata |
| `.dove/install/RESEARCH_QUALITY.md` | Package-managed substantive criteria and current-use joint conditions |
| `.dove/install/AUTHOR_PREFERENCES.md` | Package-managed full author preferences, generated from the sole editable `docs/AUTHOR_PREFERENCES.md` source |
| `.dove/install/DOCTOR.md` | Optional host-maintained natural-language feedback about Dove itself |
| `.dove/reviews/**` | Durable explicit isolated-review exchange records, not authored Review Markdown or installed resources |
| `.dove/runs/**` | Durable local command journals/logs, not Experiment documents or scientific conclusions |
| Legacy research and archives | User-owned material preserved in place |

Research Markdown has no schema/version, fixed headings, frontmatter, generated IDs, enums, machine indexes, counts, or research hashes. Organize it through ordinary host rename, move, relink, and consolidation operations, not a migration framework or runtime fallback. There is no research-state MCP service, Research Format runtime, Claim store, or Research Spine schema/ledger. The prompt hook may read the bounded project identity card to display it but does not write research state or create a maintenance trigger; its host contract belongs in [Hook Guidelines](./hook-guidelines.md).

## Maintenance triggers

- Create or revise requested artifacts when the task needs them. Maintain additional Dove research Markdown other than Lessons only when explicitly asked to record/update/save, when results materially change the mainline, conclusion, decision, or priority, or when evidence and continuation context are genuinely useful. Invocation alone does not justify a document.
- Read relevant notes and artifacts, not the entire research tree. Prefer an existing topic document over duplicates; use readable names and ordinary links.
- Maintain a short project-owned identity card in the research context: Mainline in the user's own words, inputs/outputs/completion criteria, rejected approaches, user prohibitions, current route, next core action, and hard blocker. Keep `RESEARCH.md` a brief entry point; move detailed process history into topic files. Update the card when the user confirms or corrects goals or prohibitions, even during assessment-only work; do not treat long overviews or latest records as the mainline. Statusline reads the card; Status reports existing evidence read-only. The card is not package-managed, an acceptance gate, or a Research Spine ledger.
- Missions can preserve bounded work and branches; Sources preserve citations and what was actually inspected; Claims remain scoped prose, tables, or useful documents. A Mission may append actual results, corrections, and later judgments, but must not retrospectively rewrite its entering question, proposition, or scope to appear aimed at a later task. When useful under an existing maintenance trigger, preserve the original result, material task-identity changes, and whether a new branch remains provisional or has user authorization as the mainline. This is semantic fidelity, not mandatory headings, a new file, append-only storage, IDs, ledgers, or runtime enforcement. Experiment recording order and Review return/author-handling boundaries are owned by [Component Guidelines](./component-guidelines.md).
- Lessons are optional researcher-owned, fallible experience maintained under a separate reusable-value threshold. Before the first consequential choice for the current request, or after a correction or recurring failure exposes a possibly shared mistaken premise, the author side checks `lessons/LESSONS.md` once for that question when it has not already done so, then reads only directly relevant or plausibly decision-changing links. Missing Lessons do not block work, require `RESEARCH.md`, or create an empty index. When actual work yields an insight likely to improve a future choice or prevent recurrence, preserve the narrowest Lesson within the existing author-side write scope even if the mainline or conclusion did not change and no Lessons Skill was invoked. For a transferable failed route, retain the mistaken premise or shared cause, which earlier grounds still apply, the repair or better mechanism it informs, and its actual basis, applicability, counterexamples, and transfer limits; the Lesson is a lead, not proof, repair, or a substitute for the next permitted action. Reflection after repeated local failures or compact/resume is main-agent reasoning, not an automatic maintenance trigger or time quota for Lessons; only a reusable grounded insight within the existing write scope warrants recording. Omit routine progress, transient status, one-off tool failures, and non-transferable bugs. A read-only status query does not itself trigger general document maintenance, but a user's behavioral correction updates the identity card even when supplied with Status or assessment-only wording; record a grounded transferable Lesson when appropriate. Isolated review receives neither author Lessons nor maintenance authority. Lessons do not carry package-default author preferences or replace either managed reference, and are not evidence or a completion certificate. Do not copy default preferences into the research tree to make them reachable.
- `DOCTOR.md` records explicit user feedback about Dove or actual Dove integration, routing, Skill, document, or guidance failures. It is not CLI-owned, a generated JSON projection, an issue lifecycle, or a general project/tool failure log; no fixed template, IDs, statuses, severity, or counters.

Pure read-only requests and Status queries do not authorize unrelated maintenance; user corrections are their own trigger for updating the behavioral identity and reusable Lessons.

## Lifecycle preservation

- The two exact reference files are shared once across selected hosts, not ownership of `.dove/install/` as a whole. Explicit update/reinstall manages their package content; uninstall removes still-owned references. Neither reference is research evidence or a user Lesson. Read triggers belong in [Component Guidelines](./component-guidelines.md), resource generation in [Directory Structure](./directory-structure.md), and replacement protections in [Type Safety](./type-safety.md).
- `init` creates integration and its manifest transactionally. It adds only the minimal researcher-owned `RESEARCH.md` bootstrap when the research directory is absent. Existing research trees remain untouched even without an overview; output must report whether a bootstrap was actually written.
- `update`, read-only product SessionStart, `reinstall`, and `uninstall` preserve existing `.dove/research/**`, `.dove/reviews/**`, `.dove/runs/**`, `.dove/install/DOCTOR.md`, and ordinary project files. They do not create missing summaries, complete navigation, replace Lessons, or delete retired researcher-visible material. Reinstall rebuilds only package-managed integration.
- Legacy research data is detected read-only and left in place: no automatic conversion, deletion, normalization, or fallback reader. Unsupported installation manifests are blocked; there is no migration success path.
- `doctor` is a read-only software/readability diagnostic, not research repair or a scientific health score. Missing optional summaries are not corruption.

Host fragment retirement and SessionStart behavior belong in [Hook Guidelines](./hook-guidelines.md). Replacement conflicts, confirmation, containment, and transactions belong in [Type Safety](./type-safety.md).
