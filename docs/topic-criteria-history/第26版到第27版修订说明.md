# 第26版到第27版修订说明

日期：2026-10-15。依据用户原话：“我们选题后就要定主线啊，定主线后就按正常科研项目进行后续开发啊”，以及“解决选题过程遇到的这个问题”。

## 修的是什么缺陷

第26版同时规定：选题与理论开题期不运行模型、不做诊断（§1.2）；理论开题须“核心方法合同闭合”（2.2表）；“核心算法仍未定义”不宜推荐（§3.3）。而推荐给用户选主线被当成了理论开题。结果：方法只能靠读论文推，推出的思路逐个撞上已有工作，推荐不出、主线定不下来，也就进不了本该让方法长出来的“诊断—设计—实验”。point1 在此循环中经历了 25 轮小实验和一整天静态选题。

## 改了哪几处（其余条文未动）

1. 版本头与说明：第27版，选题出口改为用户选定主线。
2. §1.2：“不运行模型、不做诊断”限定在选题阶段（选定主线之前）；新增一条——用户选定主线时一并确认主线内诊断与资源授权，此后不逐次申请；理论开题报告改称主线内里程碑，仍不自动授权正式尝试。
3. 2.2 表：在“方法候选”与“理论开题”之间加“选定主线”一行（依据：任务后果、近邻已查清且有剩余空间、至少一个有来源的方法思路、关键未知及主线第一步；不要求闭合方法、开题报告或实验）；“理论开题”标为主线内，可用主线诊断结果。
4. §3.1：注明第三部分判断的是主线内的理论开题报告，选定主线不以其全部满足为前提。
5. §3.3：“核心算法仍未定义”只阻止写成理论开题报告，不阻止推荐为主线；其余阻塞照旧也阻止推荐为主线。
6. §5.1：第4步改为“选题在一轮内收口，给 2–3 个可选主线（只有一个扎实就给一个，不凑数）”；第5步改为“选定主线后：诊断 → 设计核心方法 → 方法闭合时写理论开题报告 → 按5.4写协议做正式尝试”。
7. §5.3 表：新增“推荐为主线”，原“推荐理论开题”标为主线内。
8. §6.1 第6项、§6.2 标题、历史索引和结尾句相应调整。

## 未改变

A会目标、方法贡献偏好、选题阶段不做实验、GPU 与资源规则、近邻与覆盖判断、学术底线、正式尝试协议、既有候选与停止决定。
