## 一、Dove 是什么

Dove 是装在每个科研项目里的研究搭档层。它让 Claude Code 里的模型自主推进研究，你只做少量纠偏。

它不替模型思考。它做三件事：
1. 在对的时刻，把对的问题和事实摆到模型面前；
2. 模型自己做不好的事，由它替你来算、替你来问；
3. 真正需要判断的事交给你，并且让你一眼看懂。

各方的角色：
- **你**：平时看面板和状态栏。只在三类时刻拍板：定主线和主指标；看新方法的设计；停滞或超时时，选继续、换方法还是换方向。
- **宿主**：自主往前推。在固定时刻回答固定的问题；只为三类情况停下来，不为汇报而停。
- **导师**：在决定点独立判断，会提出疑问，不只盖章。

## 三、一轮研究怎么走

1. **主线确认**：先搭真实评测（官方指标、真实开发集、最强的外部方法），在 EVAL 开头写上主指标，你确认一次。
2. **动手做新方法前**：写方法设计，回答四个问题：
   - 做成要到什么程度（参照目标档次真实录用的论文）；
   - 本领域的高手会怎么做，别的领域怎么解这类问题；
   - 第一个真实结果多久能出；
   - 这一步为什么能改善原问题、能改善多少。

   要说明和导师笔记里那些被否掉的方法有什么不同，并按研究标准里"从问题到方法"来推。写好后给你看，你看过再开工。
3. **开一轮**：说明里写五样：一句话说清做什么、对准哪一维、怎样算成、规模多大以及为什么够、哪天见分晓。
4. **做**：诊断和小实验都在这一轮里完成；互不依赖的方案同时试；资源用足。
5. **出结果**：
   - 写判定：兑现、未兑现，或方法取舍；
   - 写这一轮改变了什么判断、下一步因此改什么、离最终结果近了多少；
   - EVAL 只记方法版本，每一行都链接到结果文件。
6. **导师**：核对判定，看是否对得上事先写的标准；更新八维判断，指出现在最卡的是哪一维；写白话研究状态和自己的笔记；在笔记里标出可以迁移到别的项目的认识。
7. **停下来的三类情况**：
   - 只有你能做的决定：主线、主指标、新方法设计、方向、资源；
   - 一轮超时一倍，或者连续两轮未兑现且没有方法取舍。这时 Dove 先引用你的原话追问，宿主回答后停下来，给你一页决定备忘；
   - 你叫停。

   等你答复的时候，宿主接着做不依赖这个决定的事。其他情况都不停，包括写汇报。
8. **你纠正时**：宿主把"下一步具体改成什么"写进下一轮的说明。

## 四、组成

### 1. 宿主读到什么、什么时候读

| 时机 | 内容 |
|---|---|

### 2. 项目档案

- **身份卡**：字段不变。研究状态由导师写，宿主原样更新。
- **轮次说明**：开头三行，`对准：维度名`、`见分晓：YYYY-MM-DD`、`规模：……`；然后是一句话和预期结果。新方法时还有"方法设计"一节，三段加你的答复。
- **轮次结果**：开头一行 `判定：兑现 / 未兑现 / 方法取舍（采纳或放弃什么）`；然后写改变了什么判断、离最终结果近了多少，以及原有的固定小节。
- **EVAL**：
  - 开头一行：`主指标：名称（数据与协议）；当前最好：值（日期，第几轮）`；
  - 八维走势表：每次导师判断追加一行，写日期、轮次、八个等级、最卡的一维；表下面保留最近一次的详细依据；
  - 方法版本表：只记真实评测上的版本，数字写成"数值/分母+单位"，每行都链接结果文件。
- **导师笔记**：判断、预测有没有兑现、被否掉的方法族和原因、担忧，以及标着"可迁移："的认识。
- **其他**：论文笔记、选题卡不变。
- **旧记录一律不回改。**

### 3. Dove 自己算、自己触发的

- **计算**：
  - 超时：见分晓日期过去一倍时间，还没有结果；
  - 停滞：连续两轮未兑现，且没有方法取舍；
  - 每轮规模：从说明里摘出来；
  - 每轮账本：一轮从上一轮结果写成到本轮结果写成（时刻取会话记录里第一次写这个文件的时间），按十分钟粒度统计子代理、导师和压缩次数、你的纠正次数，同一天走好几轮也分得开，和判定、预测与实测的对账放在一起；会话记录增量读取，复用原话汇总已有的读取方式；
  - 偏差统计：同样按轮，算预测是否落在范围内、预测的变化是实际的几倍、结果里的数字能不能在链接的产物里找到、回复里的兜底词密度、新写进去的门禁词、没运行也没读取就说“已验证”“通过”的次数；只给导师和面板，不提示宿主；
  - 等你定的事：方法设计还没有你的答复、停滞或超时的决定、导师列出的待定项。
- **用你原话的追问**：用宿主收尾时的 Stop 钩子，每个条件只问一次：
  - 超时时引用你 10-11 的原话："别给自己设那麽多工程上的先后限制，主要是为了怎样最优最快的达到最终目的"，再问卡在哪里、有没有更快的路；
  - 停滞时引用你 10-23 的原话"先整理一下……"，宿主答完就停下来问你。
  - 规则：写明是"Dove 引用你某日的原话"，不收进原话汇总；宿主正在回应 Stop 钩子时不再触发；设置里可以关掉。
- **原有的继续保留**：压缩后重新定锚；更新后自动连带所有项目，并在同一会话里提示更新。

### 4. 独立判断

- **导师**
  - 调用时机：出判定时、停滞或超时时、新方法设计时、你要求时。
  - 先答三问：这段时间实质进展是什么；最近在检验核心方法还是在做工程；离最终结果还差什么、有没有更快的路。
  - 返回内容：方向和疑问、判定核对、八维判断（含最卡的一维）、下一轮说明、白话研究状态、笔记（含可迁移的认识）。
  - 读的材料：你的原话、原始结果、研究标准，以及 Dove 算出来的事实。
  - 论文追踪的判断每周做一次，或在你要求时做；返回格式写在导师自己的定义里。
- **独立审稿**：不变。

### 5. 给你的

- **项目页**（在现有页面上补齐）：
  - 主指标；
  - 八维走势；
  - 每轮的对准维度、判定和规模；
  - 超时和停滞标记；
  - 每轮的投入和结果（一轮一行），以及偏差统计；

## 六、科研思维这些内容放在哪

- **研究者立场三条**：全文放在研究标准里；同时拆进各个时刻：连接检验放在方法设计和每轮结束；先攻难点放在"对准哪一维"；区分各类失败放在写判定时。
- **从问题到方法五步**：放在研究标准里，写方法设计时按它来推。
- **八维**：放在研究标准里，导师用它判断；它的走势参与每轮"对准哪一维"。
- **四个方向**：落在方法设计的四问、见分晓日期、停滞时换方法族、导师第三问这几处，不单独成段。
- **科研心态**：变成你的原话，放进"你最常说的话"；"提出看依据、投入看价值、结论看证据"这一句留在研究标准里。
- **选题与新意**：选题部分进选题标准，新意判断进研究标准。

## 九、你最常说的话（12 句，全部为原文）

1. "说人话，汇报的时候把我当成第一次接手这个项目"（10-17）
   - 所以：第一句直接回答；先讲事，再讲术语；数字要说清是什么指标、和谁比。
2. "你得先回答我我们要解决什么问题，现有方法为什么不好，我们又想提出什么解决方法"（10-19）
   - 所以：做新方法之前，先把方法设计交给我看。
3. "是要真正能解决我们的主线目标和问题哦，不要待会等价成解决其他问题，但是主问题没有解决"（10-21）
   - 所以：换成子问题或代理指标之前，先说清它怎么改善原问题、能改善多少；进展按原问题来算。
4. "别给自己设那麽多工程上的先后限制，主要是为了怎样最优最快的达到最终目的"（10-11）
   - 所以：先在真实评测上跑通完整的第一版，再去攻瓶颈。
5. "小规模验证如果没有用那就不要一直小规模……你做小规模的意义在哪里呢"（10-13）
   - 所以：先算清预期差别和噪声，再定规模；分不出结果的小实验不做。
6. "你这感觉变成工程，不是科研了啊"（10-19）
   - 所以：核验做到够做决定就行；子代理只做具体的活；工程不算科研结果。
7. "随机种子从来都是补强论文结论用的，而不是用于改善方法"（10-18）
   - 所以：方法有缺陷就改方法，不靠补种子、加训练步数。
8. "既然有空闲的你怎么不跑，有空显卡就能跑，不要给自己套授权"（10-21）
   - 所以：限制只能来自我的原话；有资源就用。
9. "莫须有的东西不准说"（10-22）
   - 所以：数字和结论都要出自读过的文件或跑过的结果。
10. "记得科研中通用和泛化很重要，不能局限成某个狭窄场景"（10-01）
    - 所以：用没见过的真实数据和不同类型来判断通用性。
11. "那没做完你就赶紧做完呗"（10-12）
    - 所以：已经决定要做的完整实验就做完，不中途收窄。
12. "先整理一下，哪些是我们现在立刻就能做，但之前一直没有做且非常重要的，哪些是非常重要但是一直没有攻克的，有没有办法解决还是得降低要求，还有哪些是可有可无，但是我们一直再做的"（10-23）
    - 所以：停滞或超时的时候，先按这个问题整理一遍，然后来问我。

## 十二、实施和验收

1. **谁来做**：我来实施；期间 GPT 暂停 Dove 发版。
2. **怎么做**：在一个分支上一次做完，测试只测行为。
3. **发版前**：在三个真实项目的副本上重放当时的决策点（design2garment 第 088 轮、point1 第 035 轮、garment_repair 第 010 轮开工前），比较新旧规则下宿主的选择。
4. **发版后**：先在一两个项目上看一天，确认注入、追问、面板和状态栏都正常；再按轮次观察：每个项目各自走完两轮带判定的轮次，这期间除了修 bug，不改指导。按日历算不准：有的项目一周能走好几轮，有的一周都在跑同一个实验。
5. **验收**：
   - 你每轮的纠正次数有没有降（比每轮平均，不比每周）。基线：说人话，10-02 以来 23 次；跑偏，9-29 以来 27 次；设限，10-15 以来十来次；发版前各项目最近几轮的每轮平均由面板的纠正页按同样口径算出。
   - 追问触发了几次，宿主随后怎么做的。
   - 方法设计有没有先交给你。
   - 判定和对准维度有没有写。
   - 导师调用次数有没有收窄。
6. **出问题**：回退到上一版。

## 实施说明（3.5.0）

### 代码落点

- 操作说明、研究标准：`src/core/dove-research-contract.mjs`（`renderDoveOperatingManual`、`renderDoveResearchQualityReference`）。操作说明由 `src/core/ambient-policy.mjs` 渲染为 `.claude/rules/dove.md`，是唯一写操作规则的地方；Skill 只写各自的做法。
- 你最常说的话：`src/core/dove-author-preferences.mjs` 的 `DOVE_USER_SAYINGS`，安装为 `.dove/install/AUTHOR_PREFERENCES.md`；Stop 追问引用同一份原话。偏好全文仍是 `docs/AUTHOR_PREFERENCES.md`，一字不动。
- Dove 自己算的事：`src/core/round-state.mjs`（说明开头的对准、见分晓、规模，结果开头的判定，超时、停滞，主指标，八维走势，等你定的事）。每条消息的注入、状态栏、导师材料、面板都从这里取数。
- 活动量：`src/core/user-originals.mjs` 的 `refreshActivity`，复用原话汇总的增量读取，按十分钟计子代理、导师调用、上下文压缩、回复字数、兜底词、新写的门禁词和没运行就说已验证的次数，并记下每个轮次说明和结果第一次写下的时刻，存 `.dove/install/activity-index.json`；`src/core/round-ledger.mjs` 按这些时刻切分轮次汇总，并对账预测与实测、核对结果数字的出处。
- 钩子：`src/core/user-prompt-submit-hook.mjs`、`session-start-hook.mjs`、`stop-hook.mjs`；一次性提示和追问记在 `.dove/install/hook-state.json`（`src/core/hook-state.mjs`）。
- 跨项目经验、反复纠正：`src/core/cross-project.mjs`；面板页在 `src/cli/dashboard-server.mjs`。
- 导师：`src/core/dove-agent-definition.mjs`（定义）、`src/core/mentor-brief.mjs`（材料，含“Dove 算出的事实”，论文追踪每周附一次，`--watch` 强制附）。

### 与设计稿不同或设计稿没写细的地方

1. **见分晓带开始日期**：说明写成 `见分晓：YYYY-MM-DD（开始：YYYY-MM-DD）`。超时要知道预计时长，只有见分晓日期算不出“超过一倍”；没写开始日期时退回用说明文件的创建时间。
2. **跨项目经验也写成文件**：宿主看不到网页，所以除了面板页，Dove 还把汇总写进每个登记项目的 `.dove/install/CROSS_PROJECT_EXPERIENCE.md`，操作说明在“动手做新方法前”指到这份文件。面板常驻时随调度刷新，生成导师材料时也刷新。
3. **迁移待办并入旧待办里没做的两项**：新待办会替换没做完的旧待办（ar-garment、modify2、physprior 当时还挂着），所以把旧版里仍然有用的“核心能力一栏”“限制附原话”两项并进新待办，其余旧项已由新机制承担。
4. **旧轮次不催补**：每条消息的注入只对进行中的轮次提示缺对准、见分晓、规模；判定缺失只在新格式的轮次上提示。
5. **研究状态不再有字数提示**：研究状态由导师写，钩子不再提示“超过约 300 字请宿主重写”。
6. **追问开关不写进设置文件**：`stopPrompts` 没设置就当打开，`dove settings --stop-prompts off` 才写入。
7. **`.codex/`、`.opencode/` 未动**：它们是早期开发流程留下、被 git 跟踪的文件，不进发布包，设计稿没提。
8. **检查方式**：合成行为评估删除后，发版前用 `scripts/replay-decision-points.mjs` 在真实项目副本上重放决策点（开发用，不进包）。
