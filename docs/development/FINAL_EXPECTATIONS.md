# 最终期望

本文描述用户在真实使用 Dove 时应看到的结果，不表示实现、安装或软件检查已经证明这些目标。具体产品职责和记录格式见[产品需求](PRODUCT_REQUIREMENTS.md)，科研判断的完整含义见[研究模型](RESEARCH_MODEL.md)。

## 一个能承担完整研究的协作者

用户直接说明目标、问题或希望得到的结果，Dove 就应理解现场，自行选择检索、分析、实现、实验、写作、绘图、审稿或回应能力，并把结果带回同一条研究主线。用户不必理解内部文档、九个平级 Skills 或角色切换。普通 Claude 主会话是完整入口，可选的 Dove agent 和 Skills 不产生新的人格或权限；有界调查可委派，目标理解、用户澄清、执行和结果采纳仍由主会话负责。

用户说“继续”时，可见上下文已经明确就自然续接；只有答案会改变行动的歧义才需要澄清。已有确认主线不因接手而重选，明确原话不反复确认，暂定想法也不被写成承诺。用户的目标、预期贡献、完成含义和固定方法保持稳定，事实上的反证可以直接改变判断，改变用户承诺或超出授权则请用户决定。局部、只读和仅设计请求不会自动扩展成完整科研。

每个全新作者主上下文亲自阅读质量与作者偏好的中文摘要，相关全文按需查阅，压缩和恢复可复用已读内容。Claude Code 与 DSH 的 shared 指导都明确引用 `RESEARCH_QUALITY.md`，导师笔记、追踪和主会话保存职责是两宿主共同要求，不只存在于 Claude 的 agent 定义中。DSH 仍只分发 filesystem Skills，不打包原生 agent 或 hooks；没有实际独立调用能力时说明缺口，不用主会话自检冒充独立判断。

## 先拓宽候选，再由用户选择

主线尚未获用户确认时，Dove 先读项目已有的选题标准，包括 `.dove/research/topics/CRITERIA.md` 或项目自己的标准文档，再按标准确立有意义的方向。`dove topic start` 是可选工具，是否使用它不影响必读标准的责任。

用户应看到有宽度的并列候选池，而不是每轮只试一个方法、失败后不断缩窄。候选生成时先发散，不提前砍题；真实检索既审查近邻，也带回跨领域机制、矛盾、未验证假设和新的研究可能。Dove 比较后给出 2–3 个有依据的推荐，让用户选定。用户选择之前不实现方法，只做标准允许的诊断；理论开题不会被擅自改成先做实验。

选定后，Dove 把目标落实到核心机制和有效观察，而不是只把外围接口接通。规模和改动取决于能否回答问题：回答不了就扩大或换做法，能够回答就不必更大。不会默认小规模、单点补丁或一次只动一处，也不会为了显得完整而堆基础设施。核心实现无需等待穷尽检索、完整基线库或论文论证，但需要足以指导行动的机制依据、操作、资源和观察办法。

科研价值不由现成代码、接口、数据或便利指标决定。跨领域直觉可以启发创新，同功能不必同贡献，换领域或组合标签也不自证新意。Dove 按相同贡献粒度检查真实近邻，分清等价、表达覆盖、可实现性和实测效果。若问题已经解决或贡献被覆盖，应诚实说明，不为保住路线悄悄换目标；新方向的成功也不能抹去原命题的失败。

## 导师独立纠偏，而不是替执行者背书

每轮结束、连续两轮没有新科研结果、用户纠正方向或追问论文主张与故事、准备换路线，以及用户要求时，Dove 都应取得导师判断。每次独立判断用全新原生上下文，不传执行对话、不跨轮续用；同一次判断内可以澄清 2–3 个来回。

导师得到的是材料清单：真实用户原话及来源范围、项目标准、身份卡、自己的笔记、近期评测与轮次材料、改动、原始产物和论文追踪。执行者意见可以作为标明来源的附件，但不能把任务框成“批准这个局部修复”。导师始终回答四个问题：方向是否忠于用户原话，最近是在建设通用能力还是反复打补丁，距离目标和目标档次还缺什么，下一轮应该做什么及为什么。

用户应看到导师先回应上一轮异议和事实纠正，再比较过去预测与实际结果，识别方法族的共同原因和未见数据上的证据。它判断方向与时间投入，不裁定数值等价、加速、参数或评价器工程问题；这些由执行者负责。导师可以查论文和网页，但不执行或改文件，也不读取作者偏好。

导师有记忆，但记忆只来自它自己写下的 `MENTOR_NOTES.md`，不是被续用几十次的会话。每次判断后的笔记由主会话原样追加，记录判断、预测、否决的方法族及理由和仍在担心的事。它应能发现自己以前的预测没有成立，而不只是沿用执行者的叙述。

## 推进必须带来结果，也必须会停下来

Dove 应把授权研究做到能够判断的结果。完整任务与合理外部方法的公平比较回答“有没有用”，内部消融和机制对照回答“为什么有用”，二者不能替代。链路跑通、合同测试、核验完成和成功执行只证明相应工程事实，不能直接证明方法、机制或泛化。

一个方法版本可以包含协调修改；后续方法代码改变就另开版本，按全部适用协议评测，不只看修好的样本。评价错误应修正并重算可比历史方法和基线，保留旧协议结果的出处。开发可以看真值和重跑；测试用过后再改方法，必须使用此前未用于开发或测试的新数据，并在同一新样本上比较。最终留出确认才冻结、登记并一次性检验，探索结果不冒充独立确认。

每个结果先回答原问题是获得支持、被反驳、证据不足还是当前比较无法识别，再改变依赖它的方法、投入、主张和产物。有效负结果可以增加认识，不能包装成有效方法；异常或异常优异结果需要先检查实现、数据、评价和分析。不能事后换阈值、子集、代理目标或完成含义制造成功。判断已经充分时应推进或交付，不为继续评分、检索或记账劳动。

连续两轮没有新的科研结果时，必须由导师诊断；第三轮开始前向用户说明阻塞、尝试和可选行动，请用户决定继续、调整或停止。工程失败和核验失败都计入，不能以“不算科研轮”绕开。换路线或方法族时必须明说原路线、新路线和原因，需要改变确认承诺时先取得用户决定。停止依赖已被否定的命题，不等于宣布整个问题无解。

选择下一步看剩余科研价值、信息收益、结果质量、未来时间和资源，也比较替代路线、切换与停止的价值；过去花了多久不是继续投入的理由。已获授权的核心工作不逐项索要批准，真实权限拒绝则按实际范围报告，不能换路径绕过。普通状态或阻塞答复可以结束当前回复，不必假装整轮完成，也不必为了结束回复补写记录；用户明确暂停时尊重暂停。

## 用户得到质量判断，而不是工作完成分

Dove 分开说明研究对象有多好、依据有多可靠、当前用途是否满足，以及实际完成了什么。八维评价保持各自的实质含义，完整逐级判据见安装后的 `.dove/install/RESEARCH_QUALITY_FULL.md`：

| 维度 | 从低到高的实质等级 |
|---|---|
| 问题价值 | 价值不足／有限但明确／重要／重大 |
| 新颖性 | 无实质新意／有限新意／实质创新／重大或原理性创新 |
| 机制与理论 | 论证不成立／有限而成立／有力且有区分力／深入约束或统一解释 |
| 方法与可行性 | 关键不可行或不适用／部分适用／适合目标／显著整体优势 |
| 数据与评价 | 对主张无效／判断受限／对主张有效／强区分 |
| 实现 | 不满足用途／受限可用／约定范围可靠 |
| 实验与证据价值 | 无有效判断贡献／有限更新／确立相称结论／解决关键不确定性 |
| 表达与交付 | 误导或不可用／可理解但薄弱／准确清楚可用／准确且显著降低理解或使用成本 |

未知、未形成和不适用不填成零分或低档。窄而严重的问题可以有重大价值，有限新意可以形成独立贡献，经验机制不强制定理，一次性实现不因缺少通用架构降档。可靠负证据可以有很高认识价值，但不能提高失败方法的质量；设计适配可以暂判，未测效果仍然未知。

不平均序数分数、不推算录用概率，也不以其他高分抵消泄漏、无效评价、理论矛盾、必要资源缺失或贡献已被覆盖。不同用途需要不同的充分条件：探索不要求论文级完整证据，获准修复不重开新颖性审批，扩大确认性实验则应能够解决重要未知。重要结果后导师给出当前八维判断，最弱且决定性的缺口影响下一步，而不是不断追加评分日志。

用户问“达标没有、快不快、能不能”时，第一句只给结论，如“达到”“没达到”“能”“不能”或“还不知道”。随后给一两句依据，证据边界最多一句，不用“可以，但是”掩盖未达标。状态汇报用四句说明做出什么、核心是否证明、卡在哪里和正在做哪轮，不为回答状态额外跑实验或修文件。

## 短记录支持研究，追踪不等待轮次

用户应能快速读懂目标、当前证据和下一步，不需要翻阅工程日志。身份卡不超过 1200 字，包含稳定主线、目标会议或期刊档次、输入输出、完成标准、限制、近期纠正和随重要结果更新的研究状态。目标档次缺失时问一次，不自行把高目标降成应用稿。限制必须区分原话与转述、长期与某次任务范围；一次单卡安排不能变成永久单卡禁令，纠正也要改变实际做法。

每轮只有一份至多 2000 字的说明和一份至多 3000 字的结果，附属材料放普通项目目录并链接。评测表每个方法版本一行，固定列和每格 200 字上限让数字可比较，工程进程不混入其中；表下只保留至多 1000 字的当前八维评价。导师每次笔记至多 1000 字，累计超过 6000 字时由导师自己合并为至多 3000 字，主会话不替它编写记忆。记录格式及作者优先级以产品需求为准，不另建数据库、哈希或审批机制。

论文追踪在没有研究轮次时仍然有效。每次导师调用都检查初稿配置、尚未判断的新论文和最近扫描；配置仍为初稿或结果无关时，导师提出针对性修正，由主会话写回并标为 `source: mentor`。面板“立即运行”也提示修正初稿。单个宽泛词命中标题不能把无关论文选进来，限流、接口错误或检索不完整不能报告成“没有相关新论文”。

影响判断独立保存到带日期的 `watch/impact-DATE.md`，说明撞题、新基线、可借用或无关及其理由，不只藏在轮次说明中；旧说明中的判断仍保留可读。重要疑似撞题核查更完整来源，证据不足保持待判，核心贡献重叠交用户决定。没有领域扫描或距上次超过 7 天时，下一次导师调用应返回带来源、至多 2000 字的扫描，主会话保存为 `watch/scan-DATE.md`。有价值的论文要改变定位、基线或方法，而不是只增加条目。

历史记录、Lessons 和 DOCTOR 保持各自用途，`RESEARCH.md` 只是短历史索引，旧 missions、experiments 和 claims 不迁移删除。Lessons 保存有依据和迁移条件的经验，不代替证据；跨项目反复纠正可以询问是否加入全局作者偏好，不能自动修改。恢复上下文不等于必须维护所有记录或重启研究轮次。

## 来源、论文和图真正可用

用户可以要求有界文献身份或 DOI 核验，Dove 会区分发现材料、实际取得、读过内容和主张支持。元数据正确不等于全文支持，复合主张的部分支持不算整体成立。普通检索按问题取材，明确的系统综述按领域方法完成；缺少工具或来源时如实说明，不用模型记忆补当前项目事实。

写作以实际证据为基础，普通润色不悄悄强化或削弱因果性、确定性、范围、数量限定和新颖性。图工作包括搜集材料、实际绘制或重画、渲染检查、图注和可编辑源交付；定量图来自真实数据和可复现绘图，概念图可以使用合适的生成能力。重要图在真实稿件布局和接近最终尺寸下检查，不以单独预览代替可读性与论证作用。

作者可以自检全文，但不能称其为独立审稿。`dove-review` 在全新原生上下文中，只通过 Read／Grep／Glob 阅读指定当前稿件、引用结果及所供投稿与文献依据；不读作者会话、偏好、身份卡、轮次记录或旧审稿，不联网、不执行、不改稿。它检查方法是否回答问题、领域机制和文献是否正确、贡献与证据是否适合目标读者，以及最强合理反对意见。返回说明实际读过的材料，材料不足或能力不可用时明确限定判断。

意见应被忠实保存并核查，而不是当成新的实证、权限或必须照单接受的裁决。实质修订后重新独立阅读当前完整版本，旧推荐不自动继承。Rebuttal 留在作者侧，合并共同问题，核查证据并按委托回应和修订；新增引用与实验解释仍需真实材料。保存意见不自动授权改稿，写完回应也不等于问题已解决。

保留用户当前权威稿件格式；新稿仅在目标接受时默认 LaTeX，并检查真实构建或导出产物。投稿完成要求同一当前完整版本同时满足作者侧科学充分、独立审稿认为科学可接受，以及实际提交材料就绪。独立审稿缺失不降低标准，局部任务完成、可靠负结论、构建成功或格式完整都不能冒充投稿完成。

## 软件事实与真实改善分别验收

安装和升级只管理声明拥有的软件资源，保留研究、导师笔记、追踪、审稿、运行历史、DOCTOR 和普通产物。已注册项目参与连带升级，自动同步保留本地修改或删除的托管项，用户 hooks 不受接管。启动与输入 hooks 只交付上下文，不写研究或代做判断；已有状态栏不被覆盖，主线不从分支猜测。磁盘资源更新、宿主重新加载、模型实际采用和科研结果改善必须分开说明。

运行收据、锁和事务提供实际范围内的执行事实，不扩展成科学评分或崩溃恢复承诺。预算是比较和资源依据，不是自行设定的预付额度；计算以得到有效证据和交付的总时间为准，不默认 CPU 或单卡禁令。软件检查保护实现与发布，不能证明导师有效、方法泛化或论文可接受。

本次调整的行为验收回到触发问题的项目，在获准的正常使用中观察，不创建专门测试项目，也不为验证继续消费项目研究。以下都是待观察目标，不是已经取得的效果：

| 触发项目 | 正常使用中应观察的变化 |
|---|---|
| design2garmentcode | 导师不再跨轮续用或接受局部修复框题；能借自己的笔记纠偏，记录恢复为短说明、短结果和一版一行。 |
| ar-garment | 规模由问题决定，不循环做无辨别力的小试；任务限定不变成永久资源限制，判断题先答结论。 |
| point1 | 实际先读项目标准，形成并列候选，经真实检索拓宽后给用户 2–3 个选择，选定前不实现。 |
| modify2garmentcode | 工程和核验失败计入无科研结果轮数，两轮后诊断、第三轮前请用户决定；换方法族明说前后路线与原因。 |
| physprior-source-conditioned | 目标档次与用户原话一致，重要结果更新研究状态，未达目标直接说明；导师不代替执行者定工程参数。 |
| 上述相关项目 | 追踪配置得到实际修正，论文影响和每周扫描独立留存，并产生与研究有关的判断和行动。 |

发布报告分别说明软件检查做了什么、哪些资源已更新，以及在哪个项目观察到什么；尚未观察就写明未观察。短文档、成功安装或通过测试都不预先算作上述行为改善。
