# 产品需求

本文写实现和公共文件必须满足的要求：装进项目的是什么，什么时候把什么送到宿主面前，Dove 自己算什么，工具和面板做什么，怎样安装、更新和发版。研究上的含义见[研究模型](RESEARCH_MODEL.md)，用户在真实使用中应看到的结果见[最终期望](FINAL_EXPECTATIONS.md)，用户说过的全部要求见[用户需求清单](requirements/README.md)。运行时的权威文字在 `src/core/`；本文与代码对不上时以代码为准，并把本文改对。

## 装进项目的东西

目前只支持 Claude Code。每个项目装的是：

- `.claude/rules/dove.md`：操作说明，唯一写操作规则的地方。宿主每次会话自动读到。
- `.dove/install/` 下四份参考：研究标准 `RESEARCH_QUALITY.md`（导师和审稿每次读，主会话在对应时刻查），选题标准 `TOPIC_CRITERIA.md`，“用户最常说的话” `AUTHOR_PREFERENCES.md`（每个新的主上下文开头亲自读），作者偏好全文 `AUTHOR_PREFERENCES_FULL.md`（按需查）。
- `.claude/agents/`：可选入口 `dove`，导师 `dove-mentor`（只读，可检索论文和网页），审稿 `dove-review`（只读，只用 Read/Grep/Glob）。
- `.claude/commands/dove/`：research、status、source、experiment、draft、figure、review 七个平级技能，是可选入口，不是阶段或权限。
- `.claude/skills/` 下论文检索和网页阅读两个辅助技能。
- `.claude/settings.json` 里的三个钩子（会话开始、每条消息、宿主停下）和状态栏。

项目里 Dove 只建 `.dove/` 一个目录；研究目录 `.dove/research/` 属于研究者，安装不读、不补、不改写其中已有的内容，只在目录不存在时建一份简短的 `RESEARCH.md`。卸载时删掉 Dove 自己的文件，不碰用户的改动。

## 什么时候送什么

- **新会话或 /clear 之后**：提醒主会话亲自读一遍“用户最常说的话”，不交给子代理代读。
- **压缩或恢复之后**：身份卡、本轮情况、用户最近的本人原话，以及“已读过的偏好沿用，确实丢失才补读”。
- **以上两种情况都附上**项目学到的东西：导师最近一次提炼的用户“核心需求”和“约束”、做法更正、和本轮相关的几条跨项目经验；用户原话的来源路径；开关打开时的迁移任务。
- **每条用户消息**：身份卡、本轮情况，和这条消息话题相关的做法更正，用户要求反思时的提示，以及一句固定的推进提醒。指导版本更新后，本会话只提示一次“请重读操作说明和最常说的话”。后台任务通知、客户端自动提示只附一句“这是自动通知，不是用户的新要求”，不附整张卡。
- **宿主停下时**：一轮超时或停滞，引用用户原话追问一次；用户要求反思但还没写反思文件或做法更正，提醒一次；编译了 LaTeX 稿件，提醒交付前冷读。每件事只问一次，用户可以在设置里关掉这些追问。
- **状态栏**：模型和上下文余量、主线、一行轮次摘要（第几轮、对准什么、哪天见分晓、判定、是否超时）、项目绝对路径；主线很长也不挤掉轮次和路径。

注入的是从记录里读出的当前情境，不是重复的通用规则；钩子只读，不写研究记录。

## Dove 自己算的事实

能机械算出的东西由代码算，不靠宿主自报（10-23：“能机械避免的错误，让工具直接避免”）。

- 从身份卡和 `rounds/` 读出当前轮、说明开头写了的字段（对准、见分晓、规模、正向证据、可选的预测）、结果开头的判定和实测。字段缺了不催补，记录为工作服务。
- 超时：当前轮超过预计时间一倍还没有结果。停滞：最近两份判定都是未兑现、其间没有方法取舍。它们是历史判定，提示里写明“不自动表示当前仍等用户定，请读最新原话”。
- 从 EVAL 开头读主指标；从文件和导师笔记读出待用户决定的事项快照。
- 每轮的投入和结果（时长、会话数、用户纠正次数等）只在面板上作历史参考，不进导师的科研判断，也不要求每轮预测和对账（10-28：“别再堆指标和流程了”）。

## 导师材料

`dove mentor brief --project <root>` 生成导师的调用正文，内容依次是：用户原话（本人和转述分开，附来源和日期）、身份卡里的完整目标和核心能力、Dove 算出的事实、主会话明确附上的原始结果、做法更正、其他项目的可迁移认识，以及几个到期提示：长期意图对照（每三轮、出现方法取舍或用户又说了三十条原话）、导师笔记整理（超过 64KB）、论文追踪（每周一次，附清单时才做）。

导师返回的研究状态原样更新到身份卡，笔记原样追加；整理到期时旧笔记原样存到 `archive/` 再替换。

## 记录格式

身份卡、轮次说明和结果、EVAL 的格式见[使用说明](../USAGE.md#research-markdown)。解析要容忍几种常见写法（`Field: 值`、`- Field: 值`、`- **Field（说明）**：值`），读不到就照常工作，不拒绝也不改写用户的文件。旧轮次不回改，用户写的原话不改写。

## 命令和工具

- `dove topic start`：准备选题材料，候选写在 `topics/cards/`。
- `dove mentor brief`：生成导师调用正文。
- `dove watch run`、`dove watch configure`：论文追踪；导师建议的关键词、作者、会议等由主会话用 `configure` 保存，核对回执。
- `dove figure`：调图像模型出插图（可传提示词、质量、背景等），`--proof` 按最终尺寸出预览，`--compare` 出改前改后对照，`--pages` 把整篇稿件排成一张总览，标出空栏、大片空白和只放浮动体的页。
- `dove cold-read`：把编译好的 PDF 转成逐页文字和页面图，生成冷读调用正文，交给全新的 dove-review。
- `dove dashboard`、`dove settings`、`dove doctor`、`dove update`、`dove uninstall`：面板、设置、检查安装、更新、卸载。

工具缺失或失败时说明并找可用替代。已配置的工具（图像模型、论文检索、网页阅读）直接用，不逐次申请。没有 Semantic Scholar 密钥也能正常运行。

## 面板

`dove dashboard` 汇总所有登记项目，可加密码（`--password-file`），开启后所有页面和接口都要先登录，供挂到 Cloudflare 隧道从外网看。

- 每个项目一页：主线、研究范围和核心能力、研究状态、当前方法设计、轮次（对准、判定、实测、超时和停滞）、EVAL、导师笔记、做法更正和用户纠正、新论文。八维走势和每轮投入只作历史参考。
- 另有设置页（所有设置都能在前端改）、动态页、选题页、跨项目经验页和文献库。
- 面板进程每天按设置的时间跑论文追踪，也给所有登记项目预热用户原话索引。

## 论文追踪的实现

- 来源：arXiv 新提交（按作者和关键词）、Hugging Face 每日论文、OpenAlex（近邻论文的新引用、关注作者和机构），Semantic Scholar 有密钥时补会议和引用数。
- 遵守各家的限流，失败退避；接口出错、限流和覆盖不足分开报告，不说成“没有新论文”。
- 打分看相关性，也看影响力信号：每日榜、会议接收、关注的作者和机构、有没有主页或代码。宽泛的标题词不足以入选。
- 结果写进项目的 `watch/` 日期文件，每篇附中文一句话和入选理由；扫描不依赖研究轮次。

## 安装、更新与迁移

- 用户级用 npm 安装和升级，在项目里初始化后才生效。安装后 postinstall 自动连带更新所有登记且启用的项目，不一个个手动做；项目里有本地改动的文件保留原样、其余照常更新，并说清保留了哪些。
- 登记表里只放真实项目。Dove 只管自己的文件，不管 git。
- 每个版本可以带一段给宿主的迁移任务（比如在 EVAL 开头补主指标）。用户级开关 `hostMigration` 默认关闭，这台服务器上按用户要求打开；打开时由下一次钩子送达，宿主在当前工作告一段落时处理，不重跑、不改结论和用户原话。
- 更新后已打开的会话不用重开：下一条消息会提示重读一次指导。
- 不设防护、审批或挡住用户请求的门槛；核验做到够做决定为止。

## 开发与发版

- 改进以真实项目里暴露的问题为依据，直接读各项目的会话上下文，特别是用户的话。改 Dove 前先拿真实问题分析，说清怎么改，用户认可方向再动手；删改功能或说法前先查[用户需求清单](requirements/README.md)。
- 不建专门的测试项目，不在真实项目里写测试内容；要看指导改动有没有改变宿主做法，就在真实项目的副本上用新旧两版各问一次“下一步做什么”。测试覆盖功能，不加篇幅、措辞、字数这类测试。
- 发版：先合并 main，版本号在 main 的 package.json 上加一；生成资源、构建、跑 `release:check`；提交不加 Claude 署名，不 push（用户自己推）；推进 main，全局安装并连带更新各项目，重启面板；用大白话汇报一次改了什么、删了什么、要在真实使用中观察什么。
