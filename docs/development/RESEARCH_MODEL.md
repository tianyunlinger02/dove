# 研究模型

## Workspace

Workspace 是持续演进的研究主体。它保存当前项目级主线、重要证据、关键判断、真实产物和研究历史。

Workspace 主线由用户确认。它是 Auto 和所有 Mission 的上层约束，而不是 Auto 每轮重新推导的结果。

主线至少应让人理解：

- 当前真正要解决什么问题；
- 为什么这件事重要；
- 当前接受的范围和约束；
- 什么结果算主线达成；
- 哪些变化需要重新询问用户。

项目文件和研究文档可以帮助读取主线与执行现场，但不能仅因内容较新、较详细或更接近当前上下文就获得修改主线的权威。

如果 Workspace 尚无用户确认的主线，Dove 可以调查并提出候选主线，但不能在长期 Auto 中静默选择一个候选并当作已确认目标。

## Mission 与研究树

Mission 是挂在 Workspace 主线之下的一次有边界研究单元。它应服务于主线中的一个问题、假设、证据缺口、产物改进或决策。Mission 是语义性研究往返，不是数据库、队列或任务记录。

Mission 的价值是形成一次可追踪的研究往返：

1. 从主线和当前证据出发；
2. 带着明确范围执行工作；
3. 返回结果、证据、失败、未知、产物和建议；
4. 由 Workspace 吸收这些结果并更新当前判断。

Mission 完成不等于主线完成。一个 Mission 失败也不等于主线失败。

研究应形成可追溯的树。若 Mission 的目标、假设或范围发生实质改变，应结束原 Mission 并建立相关的新分支，而不是重写旧 Mission，使后来的解释覆盖当时的条件和证据。

Mission 可以产生改变主线的建议，但不能自行改变主线。需要换线时，应由用户确认新的 Workspace 主线。

## Auto

Auto 是在用户明确授权下，围绕当前已确认主线进行多轮前台自主推进的能力。它以一个外层会话承载多个内层回合：外层负责把工作保持在同一主线与边界内，内层每回合只做一项最有价值的动作，执行后吸收结果，再判断是否进入下一回合。

论文投稿时，默认以 LaTeX 源码作为权威稿件和主要工作格式；只有目标 venue 官方未提供或不接受 LaTeX 时，才根据官方要求选择其他格式。Review 的发现先作为当前判断输入处理：可吸收、拒绝、界定或暂缓，但不能把 verdict 当成主线权威。贡献充分性是一个当前判断，不是分数、checklist 或固定阶段。

Auto 的职责不是完成一套固定流程，而是重复进行同一个核心判断：

> 在当前主线、证据状态、范围和风险下，哪个可执行动作最可能推进或保护主线？

它可以直接使用 Dove 的各种能力和宿主工具，也可以执行一个或多个 Mission。能力和工具服务于行动，不决定行动顺序。

每个实质结果返回后，Auto 应判断：

- 主线的哪个判断发生了变化；
- 新证据支持、削弱还是限制了什么；
- 权威产物是否真实改善；
- 当前缺口主要属于方法、证据、实验、来源、写作还是交付；
- 是否仍有可行且可能推进主线的动作；
- 是否出现需要用户决定的方向冲突或实质阻塞。

Checkpoint 是内部重新判断点，不是默认汇报点。只要仍有可行的主线内行动，Auto 就应继续。继续标准是 materiality：下一步能否实质改变主线判断、贡献可信度或必要交付物；低价值、收益递减的润色不足以支撑无限 Auto。

Auto 不得把以下内容提升为新的主线或完成依据：

- 最近的任务列表；
- 旧 Review 或其 verdict；
- compaction summary；
- 文件数量、格式检查或测试通过；
- 一次 Mission 的完成；
- Auto 自己上一轮的乐观判断；
- 容易闭合但不改变科研判断的支撑工作。

## Auto 的停止边界

Auto 只应在下列情况下停止：

### 主线或当前明确目标已经达成

完成必须由实际证据、决策和权威产物支持，并符合用户确认的完成含义。不能由 Review recommendation、validator、文件生成或任务清空代替。

### 出现当前无法自行解除的 material blocker

阻塞必须直接影响主线达成，并且需要当前无法获得的外部数据、设备、权限、人工返回、作者信息或其他必要条件。Dove 应说明已尝试的主线内替代动作，以及为什么继续同类工作不能解决问题。

### 出现必须由用户决定的主线变化或竞争方向

当证据表明当前主线可能不成立、需要实质收窄，或多个方向会改变问题、结论、范围或资源投入时，Dove 应报告证据和候选选择，等待用户决定，不能自行换线。

### 达到用户明确设定的边界

包括明确的范围、预算、时间、安全、权限或执行边界。上下文压缩是 operational interruption，不是科研完成，也不是 material blocker；它只能要求保存准确续接点。

## 宿主连续性

宿主若实际提供 background、Monitor、Cron、loop、tmux 或等价等待能力，Dove 只在真实等待、长运行或跨回合必要时使用它们。结果返回后仍回到主线判断；这些宿主能力不是 Dove runtime、daemon、scheduler、queue 或研究数据库。

## Review

Review 是 Dove 用于反方检验和质量判断的一种能力。它先做科学判断，再在必要时看交付条件；若科学证据已经足够而交付细节仍是瓶颈，才把条件性交付检查作为重点。

它可以识别：

- 主张与证据的断裂；
- 方法、实验和解释中的薄弱点；
- 新颖性、定位和相关工作问题；
- 真实读者可能产生的误解；
- 对主线达成最有影响的风险；
- 最有判别力的下一项行动。

Review 不是 Workspace 主线的权威，不负责替用户定义研究方向，也不是 Auto 的固定阶段或通用 gate。

实现上，Review 支持五种语义用法：Direct Scientific Review 自查、条件性交付审查、独立 Reviewer 冻结交接、返回内容导入、上下文检查。它们是同一能力的用法，不是新的工作流或状态机。

自然语言可接受性建议至多是审查视角的摘要。Auto 应判断建议背后的证据和问题：严重问题成立就处理；意见不成立就向同一独立 Reviewer 提交证据 clarification 或 rebuttal；即使建议乐观，当前完整稿件和必要材料仍有主线工作时也要继续。当前 Dove 直接吸收作者侧 Review，不能把 Review 结果交给另一个内部 Agent 树处理。

需要真正独立 Reviewer 时，宿主必须提供隔离且持久的 Reviewer 上下文；不可用时 Dove 诚实报告边界，不能在同一上下文冒充独立。Reviewer 不读取作者私有 transcript、未列材料或未显式交接记录，只接收当前完整论文、权威 LaTeX/实际编译产物、证据与补充材料、venue 公开要求、必要公开相关工作以及明确 rebuttal、clarification 和变化说明。Reviewer 不通过且意见成立时，作者侧继续方法、实验、分析、来源、图表、权威稿件或交付物工作，实质变化后恢复同一 Reviewer 复审整篇；意见不成立时作者侧提交证据回复，不能自行宣布通过。

## 证据、记录和 Lessons

研究记录的目的，是保存未来判断所需的证据、条件、失败和决策，而不是建立一个越来越复杂的管理系统。

`.dove/research/` 是普通 Markdown 研究上下文。是否记录某项工作，取决于它是否改变主线、结论、优先级，或是否具有真实的恢复和证据价值。

软件检查是静态验证，主要看生成、投影、契约和边界是否一致；真实任务中的操作结果才是行为验收，主要看 Dove 是否真的守住主线、吸收证据、处理 Review、推进 Auto 并在正确边界停止。两类证据不能互相替代。

Lessons 是可复用但可质疑的经验，不是证据和命令。旧经验应在新条件下重新判断，而不能机械套用。
