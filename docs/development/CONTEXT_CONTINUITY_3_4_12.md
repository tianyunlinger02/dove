# Dove 3.4.12：压缩后回到用户原话，自动通知不再重复整卡

## 这次改什么

只改变现有两个上下文钩子的运行时行为，不新增命令、必读文件、会话指纹缓存或科研轮次。

- `SessionStart` 在 `compact`、`resume` 时复用 `refreshUserOriginals`，增量刷新已有 `.dove/install/USER_ORIGINALS.md` 和 `user-originals-index.json`。补充最近四条带时间的“本人”摘录，不取转述，每条连时间和截断标记最多 400 个 Unicode 字符。
- 补充说明：压缩摘要里“只输出文字摘要、不调用工具”等压缩指令不是用户最新要求；历史摘录不覆盖当前请求，也不扩大授权。刷新失败或没有可用原话时，只保留说明，不阻断会话、不回退到陈旧摘录。扫描未完会明确说明覆盖不完整。
- `UserPromptSubmit` 对已观察到的任务通知、定时唤醒、后台消息、明确的系统通知包装，以及精确匹配的“上一轮没有可见输出”客户端提示，只给一行版本和指导指纹，不读取或重复身份卡、研究提醒和迁移待办。用户讨论这些消息、普通系统标签及近似文本仍按普通输入送达完整上下文。

实际五项目检查发现旧索引会把“Claude 代用户转达”“【用户指出……】”“用户某日诊断结论”“用户授权……”这几种明确的第三方转述格式也标为本人。因此 SessionStart 在挑选四条前复用原有文本分类，并排除这些已观察到的转述前缀，不改写既有索引分类、不把转述当成新授权。真实用户讨论 Claude Code 或说“我授权”仍保留。此筛选不是万能的来源鉴定，未标明出处的粘贴或转述仍须由主会话结合来源判断。

自动消息的识别是已知宿主格式的窄匹配，不是用户意图分类。公开的 UserPromptSubmit 输入没有可靠的真人来源标记，因此不声称覆盖所有客户端生成的消息。指导文件仍先经过已有验证；不把输出缩短说成免除了全部验证读取。

## 写入和时间边界

1500 毫秒是尽力而为的扫描预算，不是整个钩子的硬超时；索引读取、目录遍历、排序及两个派生文件的重写仍有耗时。只允许更新这两个既有派生缓存，身份卡、科研记录、配置和迁移状态不由钩子改写。Startup、clear 维持原来的行为，不刷新原话。

## 验证与交付

功能测试覆盖源 CLI 和打包 CLI 的续接、增量原话选择、本人/转述分离、Unicode 截断、失败非阻断，以及自动消息的单行输出、无身份卡/迁移读取和普通近似文本。安装验证保留对科研、配置和迁移文件的写入保护，单独允许原话派生缓存。

最终源码与生成包的聚焦功能测试 13/13 通过；完整 `release:check` 通过（commands 41、cascade 13、runtime 99、dashboard 71 项，以及安装、卸载、review、runs、package 验证）；另行 `behavior:validate` 11/11、`pack:dry-run` 通过。独立审查覆盖了初版和实看后补充的转述筛选，未发现阻断问题。没有新增措辞锁定测试；项目没有独立 lint/typecheck 脚本。
