## 一、是不是只看了高频要求

是。原因有两层。

第一层在我：前几次审查和整改，都围着你反复提的几件事转——变成工程、自设限制、实验太小、反向排除。只说过一两次的，没有专门回头找。

第二层在 Dove 本身：它送到宿主面前的内容，本来就是按频次挑的。
- 每个新会话宿主亲自读的“你最常说的话”，13 句都是按“在各项目反复说过”选出来的。
- 做法更正的主题、跨项目经验的分类，也按最常见的纠正来分。
- 每条消息都附的那句固定提醒，讲的也是这几件事。
- 只说过一两次的要求，多数只写进了 72KB 的作者偏好全文（宿主按需查，实际很少读），或者开发文档（不装进项目）；有的哪里都没写。比如“研究性质不能退化”“一口气跑完再爆雷”“用已发表论文复验技能”“评估 Dove 时扣掉 Claude 插手的部分”，在指导文字和开发文档里都搜不到；“主会话要按导师结论改下一步”在 10-05 换机制时跟着旧机制一起没了。

## 二、只说过一两次、现在没接住的

按要紧程度排。每条给出原话日期、现在的情况，和不加新规则、不加新字段的接法。

1. **怎么判断 Dove 有没有用**
   - 原话：真实验收是让真实项目自主完成一篇合格论文（09-24，整个开发里唯一写明的验收标准）；看它是否减少了没有依据的投入和方向漂移，而不是多提醒了几次（09-07）；评估时要扣掉 Claude 插手的部分（10-04）；新规则有没有真的改变宿主做法，还没有证据（10-23）。
   - 现在：没有一个项目达到 09-24 那条。ar-garment 的 CVPR 稿是我和别的 Claude 会话大量直接介入才完成的，算不到 Dove 头上。成体系的检验也没有：10-25 只在真实项目的副本上回放过一次，比的是“当主 agent 启动”和“装进宿主”两种方式。
   - 接法：以后说“Dove 有用”，一律对着这几条讲，并把有 Claude 或你直接介入的轮次单独标出来。GPT 这版合并后，在 point1、point2 的副本上用新旧两版指导各问一次“下一步做什么”，看做法变没变。

2. **研究性质不能悄悄变（10-16）**
   - 原话：“本来应该是一个模型微调项目，或者是个少样本无监督或者自监督，怎么就变成模型参与度不高了”。Design2Garment 10-24 又出现同样的事：要的是微调或从头训专用模型，不是蒸馏大模型。
   - 现在：只检查“核心能力有没有丢”，不检查“方法还是不是你要的那一类”。身份卡的核心能力一栏，宿主写的多是任务能力，不写方法类型。
   - 接法：你说过方法类型时，原话写进现有的核心能力一栏；导师判定核对时看一眼方法还是不是这一类。

3. **主会话要按导师的结论改下一步，不采纳就说清凭什么（10-02；09-07 也说过）**
   - 原话：“主会话必须按结论改下一步”（10-02）；不采纳 Dove 的关键警告，必须说明凭什么、有什么新证据，而不是悄悄继续（09-07 贴入材料）。
   - 现在：导师的研究状态原样上卡、笔记原样存档，但主会话拿到导师的建议后该怎么办，说明里没有写。10-05 路线审查并进导师时，这一条跟着旧机制一起丢了。
   - 接法：在“请独立导师判断的时刻”那一条里补半句：按导师推荐的改法做，不做就在下一轮说明里写清依据。

4. **一口气跑完才发现出大问题、推倒重来（09-07）**

   - 现在：只管住了“小实验分不出结果”这一头。另一头——大投入前先看几条真实输出、跑起来以后早看输出、走样就停——没有写。GPT 这次还删掉了仅有的半句：“先在少量真实目标上检验这条连接”。
   - 接法：在“每轮开始”里留一句。

## 四、要你定的

**预测和对账留不留**

- 10-24 你同意把“说出的把握和证据对得上”写进开发预期；10-25 预测格式按你的意思改了。10-28 你又说“别再堆指标和流程了”。
- 实际用下来：
  - 10-25 以后，各项目 16 份轮次说明都写了预测，15 份结果写了实测。
  - 区间大多跨零：point1 写“−3 到 +6 个百分点”，point2 写“−1.2 到 +1.0”。garment_repair 连着写“0 到 1 件”“0 到 0 件”，等于预测自己做不成。
  - 结果多是“未测”或接近零，抽查的全部未兑现。对准一栏还在写八维的名字，不是具体能力。
- 也就是说，它让宿主每轮多填一项，没让宿主更敢下判断，也没换来正向结果。
- 我的建议：按 GPT 的改法拿掉每轮对账；开发预期里只留原则——说出的把握要和证据对得上，过度防御和说满两头都管；文档同步改掉对账那段。

**多宿主要不要恢复**

- 这是你从一开始就要的：04-25“中立核心 + 可选多宿主 adapter”，05-06 用一份命令清单生成各宿主适配，06-20“不只是claude吧”，06-25“claude只是我测试的一个特例”，7 月要求在 OpenCode 和 Claude Code 上轮流测，09-11 问 DSH 要不要适配。
- 10-23 整改把 DSH 删了，设计稿里写明“这一项你没表态，是我替你定的；不同意就保留”。现在只支持 Claude Code。
- 你还要用别的宿主，就从现有指导重新生成适配；只用 Claude Code，就维持现状。
