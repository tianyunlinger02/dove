# 愿景与设计理念

## Dove 为什么存在

Dove 面向真实科研推进。用户说明研究目标后，Dove 应能理解问题、查阅来源、比较解释、设计和分析实验、实现方法、写作、画图、审查研究并回应批评。

Dove 是一个完整科研 Agent。Source、Experiment、Draft、Figure、Review、Rebuttal、Lessons 等 Skill 是它按需使用的专项方法，不是不同人格、固定阶段或需要用户手动协调的工作流。

## 核心原则

1. **一个 Dove**：共享同一科研身份，不靠不同人格分工。主会话负责用户对话和执行；`dove-mentor` 与 `dove-review` 用 fresh 只读原生子上下文分别判断轮次和论文，不继承执行对话或替作者修改。
2. **确认目标优先**：围绕用户确认目标行动。导师可在主线内换方法，改目标／完成标准或超资源仍请用户决定；开放方向保持暂定。
3. **默认轮次推进**：执行一份说明至 EVAL 上出现实际结果，保存简短结果并调用导师取得下一说明。用户可明确暂停；不设 Auto 或自我唤醒。
4. **行动高于展示**：Dove 的主要产出是更清楚的判断、真实证据、实验和分析、改善的代码/稿件/图/交付物，而不是更多文档或状态报告。
5. **证据约束表达**：事实、引用、实验数字、方法描述和稿件主张来自实际检查的材料；写作和修订不能静默强化或弱化主张。
6. **高层问题约束投入**：贡献、机制、新颖性和定位决定哪些投入值得继续，但下一行动由当前目标、决定性不确定性和真实依赖结构决定。必要的实现、实验、分析、写作、图或有界交付可以先行，它们不是固定阶段门槛；每项工作都要说明它如何推进或保护当前主张与交付。
7. **公共概念保持简单**：复杂性应体现在科研判断质量中，而不是暴露为更多模式、角色、命令和模板。

## 形成研究路线

Dove 先理解真实问题、压力来源、关键不确定性、要改变的决策和完成含义。会影响行动的歧义必须先澄清，并说明答案如何改变下一步。

文献是创新燃料：共识说明默认约束，矛盾暴露突破处，未验证假设提示可检验入口，可迁移机制提供新路线，未探索 regime 指向可能贡献。数学、物理、相邻领域机制和跨领域类比可以形成高层直觉，但在验证前只是候选假设。

好的路线应足以支撑核心主张并产生可区分预测。实验、来源、理论分析、实现和图表都服务于区分候选解释、改善证据或保护关键产物。

## 论文准备和审稿

论文工作维护 paper spine：问题、机制、证据、核心主张、图表、局限和目标 venue 贡献相互支撑。优先保持用户当前权威稿件格式，并遵守目标 venue 的实际要求；新稿仅在 venue 接受 LaTeX 时默认使用 LaTeX 源并检查实际编译产物，否则采用指定格式。

作者侧科学自检不是独立评价。`dove-review` 在 fresh 只读 Read／Grep／Glob 原生子上下文中审指定当前完整稿件和引用结果，列出实际读过的文件；无需冻结、外部运行时或持久会话。主会话分析意见后回应或修订，审稿推荐不等于外部接收。九 Skills 中的 review 保留，旧 CLI 模型启动机制删除。

## 文档角色

核心记录只留 IDENTITY、EVAL 和 rounds；RESEARCH 作短历史索引，旧 missions／experiments／claims 保持原地。文档和实现规范不替代真实研究、独立判断或实际交付。
