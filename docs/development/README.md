## 使用方式

1. Vision 是人读的研究者立场总纲；运行时权威来源为 `src/core/dove-research-contract.mjs`，不把本文档变成第二份提示词或新增必读阶段。
2. Research Model 展开具体科研语义；运行时经操作说明、研究标准和导师定义送达宿主与导师。
3. Product Requirements 把语义转为实现要求。
4. Final Expectations 描述待观察结果，而不是测试清单或已验收结论；带版本号的文件保留当时发行事实。
5. 改指导时先写清要建立的正向能力，也就是怎样把事做好，再看是否还需要禁止项；只描述某次错误外形的条款，改写成对应的做法或删掉。精简删的是重复，不删关键推理。
6. 发版安装时让 postinstall 级联到全部登记项目，不要跳过；跳过会让项目里的指导和钩子落后于命令行。
7. 指导改动的好坏看宿主在决策点的做法有没有变，不比篇幅，也不只看测试通过数。
8. 删改一项功能或说法前，先在用户需求清单里查它对应哪条原话，不只照顾反复说过的几件事；用户新说的要求接着记进清单。

公共文档、实现和生成文件应与这里保持一致；真实研究进展来自项目证据、实验、稿件、图、代码、Review 和用户决策，而不是这些开发文档本身。
